Voice model memory, 2026-10-11 (mem_probe.py; sherpa-onnx 1.13.8 = the app's AAR, which bundles
ONNX Runtime 1.28.2; desktop x86, 2 decode threads like the app). MB above the process baseline.
"held" = still allocated after 40 mixed sentences, i.e. what the model keeps while you're quiet.
Run-to-run noise: ~5 MB (default run repeated: 978 / 982).

Settings go in a provider-config file (provider = "cpu:<file>"; keys: EnableCpuMemArena,
EnableMemPattern, SessionConfig.<any ONNX Runtime session key>). The app now uses the first row
marked APP for every model (stt/ort-session.cfg, SpeechToText.runtimeProvider).

  Emulated ARM (qemu-aarch64 -cpu cortex-a76, sherpa-onnx v1.13.8 linux-aarch64 build, app settings,

  Why no saving with prepacking: x86 MLAS re-packs 4-bit weights for its int8 kernels at ~0.75
  bytes/weight (4-bit + fp32 scale + block sum). ARM64 with KleidiAI packs at ~0.56 B/weight
  (4-bit + bf16 scale), so on the Quest it should land ~150-200 MB under int8 at similar
  speed: only an on-headset run can confirm it.
