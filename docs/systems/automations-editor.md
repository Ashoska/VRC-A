# Automations drag-and-drop editor

_Scope: AutomationsPage drag/reorder, promote/demote, cross-section Pinned/Cycle moves, ghost overlay, hover-to-arm._

- **Drag-and-drop editor (`AutomationsPage.kt`, scope = reorder within a list → promote/demote within a section → cross-section Pinned↔Cycle; cross-preset dragging deliberately OUT of scope).** Universal model: **UI-only until drop** — the picked item is STABLE for the whole gesture, offsets follow the finger via `graphicsLayer` (deferred reads = no per-frame recomposition), and the VM mutation fires ONCE on release, so any interrupted drag (invalid drop / tab-away / crash) reverts for free. Grab point is always the **number badge** (long-press; tap does nothing — expand is the chevron, hide is the eye — so grabbing can't toggle anything). Dragged rows are **opaque** (`lerp(surfaceVariant, primary, …)`); a **bright insertion bar** (`drawBehind`, page-scope `dropBarColor`) shows the drop position (replaced the old gap-shift). Drop targets use **absolute-position math** (dragged centre vs other rows' midpoints) for consistent placement near ends/between rows.
  - **Increment 1 — reorder within a list**: **cycle main lines** (`cycleDragIndex`/`cycleDragOffsetY`/`cycleRowHeights`, `cycleDropTarget`) and **sub-lines within a block** (shared `subDragKey`/`subDragIndex`/`subDragOffsetY`/`subRowHeights`, `subDropTarget`, `subDragHandle`/`subRowMod` — used by both the pinned `SubLineEditor` and each cycle slide's inline sub-rows). A dragged cycle line **auto-collapses its sub-lines** while held (`draggingIdx != idx` gate — cycleExpanded untouched so they reopen on drop and the gesture isn't disposed by a key change). **Auto-scroll**: `PageContainer` takes a hoisted `scrollState` + `onViewport`; near a viewport edge (`edgePx`=96dp) a `LaunchedEffect` loops `pageScroll.scrollBy` and folds the scrolled distance into `cycleDragOffsetY`. Dropped well outside a list → reverts.
    **CRITICAL gesture-survival rule (the "can't drag pinned rows / sub-lines" bug): the drag-active flag must NOT be part of a row's `key()`.** Sub-rows previously wrapped in `key(..., activeDragIndex == i)` / `key(..., subActive)` were DISPOSED+recreated the instant a drag started (the flag flips true on `onDragStart`), which cancelled the in-progress `detectDragGesturesAfterLongPress` — so only cycle MAIN lines (whose `key(idx, lineEn, expanded, subs.size)` carries no drag flag) could be dragged. Fix: keys are `key(i, sub.hidden)` / `key(idx, s, sub.hidden)` (no drag term); the `dragActive` opaque styling still updates because it's derived from the page-scope `subDragKeySnap`/`subDragIndexSnap` snapshots read INSIDE the card content lambda (forces an in-place recompose, key stable → gesture survives), and the float/drop-bar are deferred `graphicsLayer`/`drawBehind` reads of the LIVE `subDragKey` (reactive regardless of the lambda). **Post-drop expand reset**:
    `cycleExpanded` (+ `pinnedExpanded`) is keyed by INDEX, so a reorder/demote/cross-move shifts indices and would strand the expanded state on a DIFFERENT line (the "expanded line shows collapsed until placed again, and a random other line looks expanded" report). The cycle-line `onDragEnd` tracks `structuralMove` and clears `cycleExpanded` + collapses pinned after any actual move, so expand state is never stranded.
  - **Increment 2 — promote/demote within a section (Cycle)**: **demote** = drag a cycle line onto ANOTHER line's centre (`cycleDemoteHover`, middle 30–70% band) → `vm.demoteCycleLineInto` nests its rows as sub-lines of the target (green "fits" / red "won't fit" tint via `canDemoteCycleInto` + `demoteTargetValid`/`dragInvalid`; the insertion bar hides in demote mode). **Promote** = drag a cycle sub-line OUT of its block (`subDragHandle` `onOutside`) → `vm.promoteCycleSubLine` makes it its own new line.
  - **Increment 1.5 — unified auto-scroll + data-integrity guards (device-feedback round)**: (a) **Auto-scroll now runs for EVERY drag, not just cycle main lines** — the single `LaunchedEffect(cycleDragIndex, subDragKey)` loop runs while `cycleDragIndex != null || subDragKey != null` and folds the scrolled distance into whichever offset is live (`cycleDragOffsetY` or `subDragOffsetY`); `subDragHandle.onDrag` sets the shared `cycleAutoDir` from the finger vs viewport edges. Fixes "dragging Pinned / sub-lines doesn't scroll the screen". (a2) **Sub-drag finger position is read from the GRAB HANDLE's own window pos** (`subHandleTops`, an `onGloballyPositioned` on the drag-handle modifier) since the pointer position is relative to that node — the old row-level top wasn't landing for **cycle** sub-rows (they sit inside the per-line `graphicsLayer` Column), so `crossTarget`/section detection stayed dead and **cycle sub-lines never showed a cross drop bar even though pinned sub-lines did**. (b)
    **Sub-line dragged fully out of the UI reverts** (back to its sub area) instead of promoting — promote (`onOutside`) now requires `outside && withinCard`; a drop outside the card entirely falls through to revert. (c) **Cycle main-line sub-0 visibility invariant (`repairCycleMainVisibility`)**: a cycle slide's MAIN sub-line (sub 0) must NEVER be sub-level `hidden` — its visibility is the line's mute (`cycleLineEnabled`), and the editor never exposes an eye for sub 0. A pinned↔cycle move used to carry a hidden flag onto sub 0, so the line decoded as blank → **uncounted in the "N lines" summary AND non-sending while still showing its text** (tester: "shows 10 lines but says 9", found via the saved preset). The repair force-unhides sub 0 on every slide; it's wired into the load path (`setCycleLinesFromTextPreserve` → self-heals on next open and re-persists the clean form, also healing the selected preset via the autosave) and the top of `persistCycleLinesPreserve` (every mutation's output). Source-side: `promoteCycleSubLine`/`movePinnedRowToCycle` map a hidden row to a **muted** line (`cycleLineEnabled = !hidden`, sub 0 visible) instead of a hidden main line; `moveCycleLineToPinned`/`moveCycleSubToPinned` force the pinned main row (row 0, which has no eye) visible.
  - **Increment 3 — cross-section Pinned↔Cycle**: `CompactSectionCard` gained an `expandedState` (hoisted) + `modifier` param; the Pinned & Cycle cards report their window rects (`boundsInWindow`) and `sectionAt(fingerY)`/`updateCross(origin, fingerY)` set `crossTarget` when the finger is over the OTHER section (which **auto-expands** + border-highlights; a cross INTO Pinned also force-expands its sub-rows via `expanded = pinnedExpanded || crossTarget == "pinned"` so every slot shows). On drop: **cycle line → Pinned** (`vm.moveCycleLineToPinned(from, at)`), **cycle sub → Pinned** (`vm.moveCycleSubToPinned(slide, sub, at)`), **pinned row → Cycle** (`vm.movePinnedRowToCycle(subIndex, at)`, becomes a new cycle line). Cross-section takes priority over demote/reorder on drop. All cross ops cap at 3 pinned rows / 20 cycle lines and no-op (revert) when they don't fit. Menu Move up/down/Duplicate/Delete kept as fallbacks throughout.
    **Drag GHOST overlay (`AutomationsPage`, replaced the in-place `translationY` float)**: the picked-up row used to float via `graphicsLayer{translationY}` INSIDE its card — but a card CLIPS its content and is a Z-sibling of the other card, so during a cross-section drag the pill drew BEHIND the other card, and an in-place offset DESYNCED from the finger whenever a card's layout shifted (the Pinned auto-expand). Now the real row **stays in its slot and just DIMS** (`alpha 0.4`, no translation), while a **display-only copy is rendered in a page-level overlay `Box` ABOVE every card** (`zIndex(1f)`, outside all clips — `AutomationsPage`'s root is now `Box { PageContainer{...}; ghost }`). The ghost is positioned by the **ABSOLUTE finger**: `offset = dragFingerY − dragGrabPointY − overlayWinTop` (y) and `ghostLeftPx − overlayWinLeft` (x), read inside the `.offset{}` lambda (layout-phase, no recomposition → smooth).
    `dragGrabPointY` is captured ONCE on the first drag frame (`fingerY − rowTop`), so any constant anchor error cancels and the finger stays locked to its exact grab point; because `dragFingerY` recomputes off the row's live window anchor each frame, a layout shift cancels too (no jump, no drift). Row window left/width are captured (`cycleRowLeft/Width`, `subRowLeft/Width`) so the ghost matches the row's exact bounds; the ghost re-renders `CycleLineRow`/`SubLineRow` (no handlers, `dragActive=true`) from `vm` + the field maps. The drop-math offset (`cycleDragOffsetY`/`subDragOffsetY`, which folds auto-scroll) and the insertion bars are UNCHANGED — only the visual moved to the overlay. This is what stopped the earlier attempts (raw `translationY=offset` → clipped + desync; `translationY = dragVisualTop − liveRowTop` → per-frame async jitter): the rows no longer move at all, so nothing can jitter, and the ghost tracks a single synchronously-updated finger value.
    **2-second hover-to-arm + cycle-sub promote bar**: cross-section and demote no longer trigger the instant the finger passes over a target — they require a **2s continuous hold** (`pendingCross`/`pendingDemote` hold the instant hover; a `LaunchedEffect(pending…)` promotes it to the armed `crossTarget`/`cycleDemoteTarget` after `delay(2000)`, and the key-change restarts the wait so dragging PAST never arms). Arming a demote expands **only that specific cycle line's subs** (`cycleExpanded[t]=true`, per-line, not the whole card); `fingerOverCycleLine` keeps the armed target sticky so the expansion's layout shift can't disarm it. A **cycle SUB dragged OUT of its block** into the main cycle flow now shows the SAME insertion bar the cycle reorder uses (`subPromoteIndex` = `crossDropBoundary("cycle", fingerY)`, drawn in the cycle-Column `drawBehind`; the within-block bar is suppressed while promoting) and `promoteCycleSubLine(slide, sub, at)` inserts the new line at that index.
    **Nest-into-a-line for ALL source types**: hovering ANY dragged item over a cycle line's CENTRE band (2s) nests it as a **sub-line of that line** — cycle line→line is the existing `demoteCycleLineInto`; a **cycle sub** → `moveCycleSubIntoLine(fromSlide, sub, target)` and a **pinned row/sub** → `movePinnedRowIntoCycleLine(pinnedIndex, target)` are the new analogues (both append the row, `canNestIntoCycleLine` gates the 3-row cap, `persistCycleLinesPreserve` self-heals main visibility). Detection is finger-based (`cycleLineCenterUnderFinger(fingerY, exclude)`, excludes a cycle sub's own parent); the nest is armed by the SAME 2s `pendingDemote`→`cycleDemoteTarget` effect and expands only that line. For a pinned source over the cycle area, a centre-hover **nest wins over** the plain cross-to-new-line insert (`if (pendingDemote != null) pendingCross = null`); the target line shows the green/red validity tint (`cycleDemoteValid` extended: `canDemoteCycleInto` for a line source, `canNestIntoCycleLine` for a sub/pinned source). `subDragHandle` gained an `onNest` callback threaded to those VM ops.
    **Positional cross-drop + indicator**: the cross ops take an `at` insertion index (append when `< 0`); `updateCross` computes `crossDropIndex` from the finger vs the TARGET section's row midpoints (`crossDropBoundary`), and the target section draws the SAME bright insertion bar it uses for in-section reorder (added to the cycle-Column `drawBehind` when `crossTarget == "cycle"` and to `subRowMod`'s `drawBehind` for the pinned block when `crossTarget == "pinned"`) — so you can see WHERE the item lands across sections, not just that a cross is armed. The SOURCE list suppresses its own reorder bar while `crossTarget != null` (the item's bar shows in the other section). **Edge/overshoot tolerance (the "first/last line reverts if dragged a tiny bit too far" fix)**: the old revert test keyed on the dragged row's list-relative `curTop` vs a tight `draggedH * 0.8/0.9` margin, so a small over-drag past the first/last row reverted.
    Both the cycle-line and sub-line drops now accept a reorder (clamped to the nearest slot via `cycleDropTarget`/`subDropTarget`) as long as the finger is still within the section's card rect + `DRAG_ACCEPT_MARGIN` (72dp) — tracked via `dragFingerY` set each `onDrag`; only a drop COMPLETELY outside the card reverts. Cycle-sub PROMOTE (drag clearly out of the block) keeps its own `outMargin` (raised to `draggedH * 1.4f` so a tiny overshoot reorders instead of promoting).
