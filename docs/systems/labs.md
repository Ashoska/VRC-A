# UI Lab + Cardinal Lab

_Scope: The two permanent JVM harnesses (gated, never in an APK), plus the Symbol Lab converter._

- **Exception — the Cardinal Lab (deliberate, gated, not a unit test)**: `app/src/test/kotlin/com/vrca/discordbot/lab/` is a PERMANENT JVM harness (Robolectric 4.14.1 + OkHttp MockWebServer 4.12.0, both `testImplementation` only — never in any APK) that runs the REAL admin-build `DiscordBotService` (Cardinal) against a fake Discord gateway/REST and a recording Workers AI proxy. It is excluded from every normal test task unless `-PcardinalLab` is passed (`app/build.gradle` `testOptions.unitTests.all { exclude '**/discordbot/lab/**' }`), so `./gradlew test` is unaffected. Kept because the user asked for a way to talk to the bot hundreds of times and see its prompts, memory and cost without screenshots. Run: `tools/cardinal-lab/lab.sh run tools/cardinal-lab/scripts/<script>.txt` (or `lab.sh interactive` + `labctl.py`); output lands in git-ignored `lab-runs/<run>/`. Do not delete it as "test clutter".

- **UI Lab lag check (`perf start <name> [heavy=N]` / `perf stop`, UiLabDriver)**: so UI lag is caught in the lab, not only after a GitHub build on the headset (user). Counts every composable call per frame through Compose's tracing hook (`Composer.setTracer`; the compiler puts the hook in every composable), times each frame's main-thread work (looper + layout, before any `record` capture), and reports: heavy frames (>= N calls, default 1000) with the composables that ran (VRC-A's own first), the longest run of frames each re-running >= 20 VRC-A composables with what re-ran (the signature of an animation value read in composition: it found the boot screen rebuilding for 48 frames from never-equal logo coordinates state), and frame times. **Limits, measured**: a warmed-up JVM does in ~70 ms what took the Quest 0.78 s (the hand-off rebuild: lab timing of old vs fixed code differed by ~4 ms, and their call counts were identical, since re-run parents with skipped children barely register), so there is NO reliable lab-ms → Quest-ms factor (`QUEST_FACTOR` stays 1.0) and the check can't prove "no lag"; it finds the WORK (rebuild streaks, heavy frames, what ran) to fix before a build. Draw isn't timed (Robolectric only draws for shots). The lab runs an old version number, so a forced-update dialog opens at the hand-off and makes those frames heavier than on a device. Pair with `show headsetboot full discord=6000` (simulated Discord RPC).
- **Exception — the UI Lab (deliberate, gated)**: `app/src/test/kotlin/com/vrca/uilab/` runs the REAL app UI on the JVM (Robolectric NATIVE graphics), drives it like a user and saves PNGs; full docs in `tools/ui-lab/README.md`. `ui.sh shot|run|serve <admin|headset|public>` (+ `uictl.sh` for the live server, ~0.4 s per command; `sheet.py` makes contact sheets), output in git-ignored `ui-shots/`. Commands (`UiLabDriver.kt`): `shot`, `record start <name> [ms]`/`record stop` (animations: a frame every `ms` of app time through each `wait`/post-action settle; writes `<name>-frames.png`, a timestamped filmstrip grid of ≤ 24 frames, and `<name>-frames/` (every frame ≤ 1024 px + `times.txt`), which `tools/ui-lab/gif.py` (run by `ui.sh`/`uictl.sh` after each run) turns into `<name>.gif` at real speed: the unit-test classpath is the Android SDK's, without javax.imageio. Robolectric adds/removes windows instantly, so the renderer emulates Android's dialog window animation on the lab clock (`trackWindows`/`render`: TYPE_APPLICATION windows fade + scale 90%→100% over 200 ms, decelerating in, accelerating out from their last rendered look, dim with them); Compose popups animate inside Compose already), `tap/long <text> [#n]`, `type`, `typein`, `scroll`, `scrollto`, `back`, `wait`, `tree`, `set/get <vmField | Object.prop>` (reflection on `<name>$delegate` MutableState / `_name` StateFlow / setter),
  `preset <name>` and `show <name>` (`UiLabScenes.kt`: presets for presence/roster/alerts/incident/sending/nowplaying/warned/banned/auth-dead/owner/osc-params (sample avatar params for the dictation Listen trigger)/voice-* (dictation: `voice` installs a stand-in pack, sparse files at the exact sizes `SpeechPacks.isInstalled` checks, so the app's own check passes; `voice-listening/-hearing/-loading/-stopping/-paused/-trigger/-learning/-teach-loading/-downloading/-stopped/-restored` add a state (`-stopped`/`-restored`: the "Android closed VRC-A" note), each resetting the last; expand Manual Send to see them)…; shows for gated screens: update, whatsnew, confirm, timezone, boot, crash, banned, tos, onboarding N, login), `root screen|app`.
  Driving uses Compose semantics across every window (`RootForTest` in `WindowManagerGlobal.mViews`); `shot` composites all windows in z-order with dimming.
  **Real input** (user ask: the lab couldn't catch covered buttons or drive drags): `tap`/`long` run the element's semantics action (reach it even when covered); `touch`/`press`/`drag`/`swipe`/`hover` build real `MotionEvent`s (finger: SOURCE_TOUCHSCREEN; hover: mouse) and send them to the window an input dispatcher would pick (`windowAt`: top window containing the point, or the top touch-modal one, i.e. no FLAG_NOT_FOCUSABLE/FLAG_NOT_TOUCH_MODAL: a dialog or focusable menu takes every touch, and one outside closes it on the lift) via its root view's `dispatchTouchEvent`/`dispatchGenericMotionEvent`, in window coordinates (`offsetLocation`; raw stays on screen, which Compose uses to place the window). `placeOf` (gravity + x/y) positions windows for both drawing and aiming. Gestures run a move per 16 ms frame on the app clock, so long-press (`detectDragGesturesAfterLongPress` in the Chatbox editor), velocity (swipes fling) and hold timers behave as on the device. Results name what the touch landed on (`whatsAt`: deepest semantics node with OnClick/OnLongClick/SetProgress at the point, later = on top) and flag `(!)` covered/no-taker/dialog-took-it.
  Verified: slider tap + drag, cycle-line reorder (filmstrip), outside-tap dialog close, preset-chip hold-to-peek, swipe fling, hover state layer (the top-bar icons have no hover highlight, on purpose: the headset theme's `NoHoverRippleTheme`, Quest hover-exit is unreliable; Material 3 buttons don't use it and still highlight). Headset lab size 1024x640dp = `FixedPanel`'s design size; `--qualifiers w1440dp-h900dp-land-xhdpi` etc. show the zoomed result of a resized panel.
  **`targets`**: tappable nodes reachable now (centre's window = their window), covered (another unrelated tappable on top at the centre) / tiny (both sides < 32 dp) / small (a side < 48 dp), optional boxed PNG. **Toasts**: `trackToasts` reads Robolectric's shown-toast list each frame (text via ShadowToast's private `text`), queues them (2 s / 3.5 s), `drawToast` draws them over everything; the command result appends `| toast "..."`. One-shot runs print every line of a multi-line result (`tree`/`targets` showed only their first line: ui.sh passes only `[uilab]` lines). Results are ASCII only (Gradle's console turned → into ?). Preset `cycle` = four cycle lines.
  Robolectric's choreographer is `setPaused(true)` + 16 ms frames, otherwise an endless spinner re-posts frames at the same instant and the looper never idles.
  **Frame loop = a headset's** (`UiLabDriver.settle`): one 16 ms frame of app (looper) time per step, then a layout pass on every Compose window (`RootForTest.measureAndLayoutForTest`). Robolectric never draws on its own and Compose measures/lays out inside draw, so before this the layout only moved when a `shot` drew the screen: scroll extents, bring-into-view and `tree` positions were stale, and Manual Send didn't auto-scroll on expand in the lab although it does on the device. Lab runs also set `kotlinx.coroutines.main.delay=true` (app/build.gradle) so `delay()` runs on the same app clock as animations: wall-time delays fired "early" against the JVM's slow frames (the 120 ms bring-into-view ran before the first expand frame, so it found nothing to scroll; flaky on a cold start). A real sleep keeps app time from outrunning real time, so network replies still land within a `wait`.
  **Headset = the real 1024x640 dp panel only**: `ui.sh` refuses `--tall` for headset (a 3x-tall render stretched the columns and showed a huge gap above the bottom bar that the device never has; the user flagged it). Show long content with `scrollto`/`scroll` like the device. `tap <label>` falls back to the unlabeled control on the same line (a `ToggleRow`'s Switch: `tap Scroll`), and `back` sends a real BACK key to a dialog window (Compose dialogs have no Dismiss semantics).
  `scrollto` steps through every scroll area that can still go down (top window first, screen order) until the text exists — lazy lists only build rows as they scroll in, and scrolling just the LARGEST area missed a list beside a bigger pane (voice picker); `scrollto` and `tree` use a node's UNCLIPPED position (`positionInRoot`; `boundsInRoot` of a scrolled-out node is all zeros, which sent `scrollto` the wrong way); `tree` marks such nodes "(off-screen)". `set` on a field that's currently null takes a typed literal (`12L`, `12`, `1.5f`, `true`): erased generics gave it no type, and writing "1240" into a `MutableState<Long?>` crashed the composition. Only runs with `-PuiLab` (other test runs exclude `**/uilab/**`). `UiLabApp` (a `VrcaApplication` subclass — why `VrcaApplication` is `open`) points Firebase at a fake project + dead emulator port by default, adds a fake external-storage dir, installs `FakeAndroidKeyStore`, swaps the exit-10 crash handler for a logging one. Production hooks for the lab: `UpdateDialog`/`CrashScreen`/`BannedScreen` (VrcaApp.kt), `BootScreen`/`AppBoot`/`BootReveal` and `WhatsNewDialog` are `internal` (were private), and `AdminLabAccess.forceOwner` (AdminScreen.kt, never set by the app) opens the admin panel without the owner account. **VRChat alt**: `tools/ui-lab/vrc-login.sh` logs in the user's alt (Robo-Gremlin). The password is an environment API credential for `api.vrchat.cloud` that the agent proxy adds, never visible here.
  `vrc-login.sh <code>` takes the emailed code (ask the user; each new session needs one), the session lands in `ui-shots/.vrc/`, and `UiLabApp` seeds it into `VrchatAuthManager` (reflection on `saveSession`) + publishes the real `fetchPresence`. **`--firestore`** uses the real Firebase project under a fixed lab device id per flavor (`sha256("uilab:<flavor>")`); lab builds report version 279 (no CI run number) — expected. Use the lab to check layout/fit after every UI change before asking the user to build.
  **Cloud-session first run (fixed 2026-10-16: every fresh session's first lab run failed)**: Maven Central (`repo.maven.apache.org`/`repo1.maven.org`) answers the shared cloud egress with HTTP 429, so `settings.gradle` lists Google's mirror `maven-central.storage-download.googleapis.com/maven2/` before `gradlePluginPortal()`/`mavenCentral()` (both kept as fallback), and `app/build.gradle` sets `robolectric.dependency.repo.url` to the same mirror (Robolectric fetches its `android-all-instrumented` jar at test time, outside Gradle). `ui.sh` also runs `.claude/hooks/session-start.sh` itself when the SDK is missing (a session started outside the repo folder never runs the hook) and passes Gradle's resolve/429/SDK errors through its filter (before it showed only "BUILD FAILED"). Timing: the first run in a session is still minutes (SDK install + dependency download + compile); after that a one-shot run is ~20 s.
  **Recording a full-screen `show`** (boot, crash, banned, tos, onboarding, login) starts on that screen: `startRecordingFresh` drops the "before" frame, since a full-screen show stands in for the screen opening fresh and the previous lab screen never appears on a device (the user saw Home flash before the boot intro). **Renderer gap**: a `graphicsLayer`/`alpha` layer that is see-through AND whose content spills past its bounds (e.g. a `requiredHeight` child bigger than its box) drew nothing in the software renderer while alpha < 1; put the alpha on the content itself (BootScreen's logo fade does).

- **Symbol Lab** (`tools/symbol-lab/symbol.py`, README there; user ask 2026-10-16: "a converter I can let you use when I give you a fan-made symbol"): a PNG/JPG/WEBP drawing → compact SVG path data in the boot wall's 100x100 box → the `BootSymbol.fromSvg("name", "M…")` line for `BootSymbols` + a preview PNG (original | traced | on the wall) in `ui-shots/symbols/`.
  - **Line drawings** trace the stroke CENTRE (900 px resample + blur, skeletonize, chain walk), each line lightly Gaussian-smoothed along its length (`--smooth`, default 0.6) and then FITTED with cubic Béziers directly (Schneider's Graphics Gems algorithm: one curve per stretch between corners, split where it strays more than `--detail` box units, default 0.25, from the trace, Newton re-parameterised). Replaced simplify-to-points-then-interpolate, which made small round parts pointy or flat (user, Niko: hair curls, mouth). A corner is a CONCENTRATED turn (at half the distance it still turns >= 65% as much), so tight curves stay curves. Limit: details smaller than the pen line's own thickness (Niko's mouth-top dip) average out in the centreline; shape such a stroke by hand in the path; small round solid blobs (eyes) are found as whole shapes BEFORE tracing (their centreline is often a tiny branched cluster that the chain walk split and dropped as spurs: a fan drawing lost both eyes) and become small circles (round = max side ≤ 1.6x min side, so short dashes stay lines), spurs off junctions (scaled to line thickness) dropped, meeting ends joined; `--mode outline` traces filled shapes' edges. Needs `pip install scikit-image pillow` (not a Gradle dependency, never in an APK). Typical output 1-3 KB per symbol.
- **Logo trace** (`tools/symbol-lab/logo_trace.py`, needs `pip install potracer`): traces the white-on-transparent logo (`tools/symbol-lab/source/vrca_logo_bar.png`, kept OUT of the APK) into the filled vector `res/drawable/vrca_logo_vector.xml` used by the headset top bar and boot screen. Unlike `symbol.py` (centre-line strokes for thin doodles) it keeps the filled outline shapes, so the logo's outlined letters survive. Re-run it if the logo art changes.
- **Boot cat loops** (`tools/symbol-lab/boot_cat_avd.py`): writes the boot cat's thinking loop (4 timing variants, `res/drawable/boot_cat_think_0..3.xml`) and calm Background loop (`boot_cat_calm.xml`) as AnimatedVectorDrawables from the head path + timing tracks; prints each variant's starting eye offset for `BootCat.THINK_START_DX`. Run from the repo root after changing the head or timings. The UI Lab sets `BootCatLab.drawLoops` (in `UiLabApp`) so the same loops are drawn in Compose there (the JVM can't play AVDs). `show boot demo` now includes a Discord fail + retry and a skipped row, to show every reaction.
