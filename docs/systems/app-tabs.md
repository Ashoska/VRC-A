# App tabs: Home, Automations page, VRChat tab, Settings, IP field

_Scope: Bottom nav, Home layout (preview, quick toggles, connection, setup health), VRChat tab header, Settings page, IpField slots._

- **IpField**: Multi-slot IP field component with 3 named slots (Home/Hotspot/Other). Uses local state tracking (not async DataStore) for immediate slot switching without cross-contamination. Supports per-slot editing and auto-migration from legacy single IP key. The Apply button and the slot-1 migration LaunchedEffect call `repo.saveIpSlotAddress(slot, address)` rather than `saveIpSlot(slot, name, address)` — only the auto-save debounce in the expanded slot editor is allowed to write the slot name. This prevents the placeholder defaults from `collectAsState(initial = "Home"|"Hotspot"|"Other")` from overwriting the user's saved name when DataStore hasn't yet emitted its real value. **The quick-edit `editBuffer` reflects ONLY the selected slot's saved address — it must NOT fall back to `uiState.ipAddress`** (the last-applied RUNTIME ip, which belongs to whatever slot was last equipped). On a tab re-entry `currentSlot` briefly defaults to 1 while the slot's DataStore value is still the placeholder `""`; the old fallback would then fill the field with a *different* slot's ip, and an Apply wrote that into the wrong slot (the "slot 2 overrides slot 1" bug).
  Worst case now the field is briefly blank (Apply is blocked on blank) and self-corrects once DataStore emits. **The "slot contents clone to slot 1 on tab re-entry" bug** (slot 2's IP overwriting a *populated* slot 1 after editing slot 1 → switching to slot 2 → leaving the tab → returning → switching back to slot 1) was caused by the **expanded-editor auto-save debounce** (`LaunchedEffect(n1,a1)` etc.). That debounce runs unconditionally on every fresh composition (tabs render via `when(p)` in `VrcaScreen.kt`, so leaving/returning to Home DISPOSES and re-composes `IpField` — all `remember` resets). The per-slot buffers (`a1/a2/a3`) seed from `collectAsState`'s initial value then "follow" DataStore via the `LaunchedEffect(ipNAddress)` effects; a follow-vs-debounce race could persist a buffer that merely SYNCED from DataStore rather than one the user typed, overwriting a populated slot. **Fix: per-slot `dirty` flags** (`dirty1/dirty2/dirty3`) set true ONLY in the editor `TextField` `onValueChange` (real user typing); the follow effects deliberately never set them, and each debounce `return@LaunchedEffect`s unless its slot is dirty.
  So a buffer that only mirrored DataStore is never written back — cloning is structurally impossible regardless of composition/lifecycle races. (This is build-variant-independent: `IpField` is identical across public/admin and no Firestore sync path reads/writes the slot addresses; it presented as "public-only" purely from differing per-install slot state and from the public install running an older released APK that predated the fixes.) **Secondary hardening — the slot-1 legacy migration is a race-free ONE-SHOT** (`LaunchedEffect(Unit)` reading PERSISTED values via `.first()`, gated by the `ip_slot1_migrated` DataStore flag so it runs at most once and never re-fires on recomposition/tab re-entry). It only copies the legacy `IP` key into slot 1 when `activeIpSlot == 1 && ip1Address.isBlank()`; the old reactive `LaunchedEffect(ip1Address, uiState.ipAddress)` re-fired on every tab re-entry and, because `repo.ipAddress`/the legacy `IP` key tracks the ACTIVE slot, copied the equipped slot's IP into an EMPTY slot 1. The `slot == 1` guard guarantees a non-slot-1 address can never be written into slot 1.

### Navigation

- Bottom nav: Home, Automations, **Media** (formerly "Music" — renamed since the NowPlaying block now covers YouTube videos too; enum constant stays `AppPage.Music`, only the display label/`title` changed), VRChat (4 items)

- **Automations (Phase 5 revamp, `AutomationsPage.kt`)**: the inner Pinned/Cycle `TabRow` is GONE (`ChatboxAutomationsTab` enum deleted from `VrcaScreen.kt`) — both features stack as `CompactSectionCard`s with live collapsed summaries (Pinned: the message text + ON/OFF `KitStatusChip`; Cycle: "5 lines · 10s · now: '…'" — the `now:` part uses the new public `vm.cycleCurrentLine()` and shows only while sending). Presets are a horizontally-scrolling **chip row** (`PresetChip`): tap = load/equip, long-press = peek dialog (full content via the new `vm.getCyclePresetFull(slot)`, with Load + "Save current here" buttons — Save lives ONLY in the peek dialog now); the equipped chip is highlighted by content-match (no "Selected" label). Editors have an inline **`CharBudgetMeter`** ("87/144", amber >114, red >144; mirrors the private `VRC_MAX_CHARS`) — always on for Pinned, per-line only past 100 chars for Cycle. Cycle's 10-field line editor + speed dropdown are unchanged.

- **VRChat tab (Phase 7 revamp, `VrchatPage.kt`)**: the two stacked identity cards (connection status + presence) are MERGED into one header `ElevatedCard`: `SelfAvatar` (the user's OWN VRChat+ pic via Coil through `VrchatImageLoader` — it attaches THIS device's session cookie, so it works on the public build too; initial-circle fallback; status dot pinned bottom-end) + name + colored status text + the user's status DESCRIPTION verbatim (e.g. "stars :0" — it's their VRChat status text, do NOT "fix" it) + a chips row (platform `Badge`, trust-rank `Badge` from the new `VrcUserPresence.trustRank` field — `fetchPresence` now extracts the highest `system_trust_*` tag from `/auth/user` + `/users/{id}` — and a small "RPC ●" chip when `discordSessionSeeded`, green dot when CONNECTED) + the world line (name + player count) + **friends online count** ("N of M friends online", `Icons.Filled.Group`). Sign out (error-tinted `Logout` icon) and View Profile (`OpenInNew`) are small trailing `IconButton`s. **Friends online count is FREE**:
  `VrchatPipelineState.friendsOnlineFlow` (`Pair(online,total)?`) is published by `VrchatPipelineService.publishFriendsOnline()` from the in-memory `friendsCache` on every cache mutation (`persistFriendsCache`) + restore — zero API calls. **Online predicate is STATUS-primary (over-count fix)**: `status` is authoritative — `"offline"` ⇒ offline, any other non-blank value (active/join me/ask me/busy) ⇒ online; `location` is consulted ONLY when `status` is blank (WS friend-online/friend-location payloads don't always carry `user.status`, so a live world location proves online then). **`location="offline"` is NOT an offline signal on its own** — VRChat uses it for a friend who is online on the WEBSITE but not in any world, so keying offline off location would drop website-active friends. This replaced an older `status-OR-location` predicate that counted a friend online if EITHER field looked online: a friend-update setting `status="offline"` while leaving a STALE world in `location` (VRChat often updates only one field) kept them counted → the "friends online way higher than actual, reopening fixes it" bug.
  **The confirmed `friend-offline` handler now marks the cache entry `status="offline"/location="offline"`** (after the flap cooldown) — previously the entry kept its stale online status forever, which would have frozen the count. **The in-app alerts header gains filter chips** (All / Friends / Groups / Bio — `alertMatchesFilter` keyed on alert-group-id prefixes: `announcement_`/`event_` = Groups, `bio_` = Bio, rest = Friends). **The Discord RPC card and the duplicated About/trust card are DELETED from this tab** — full Discord management (status line, enable `ToggleRow`, sign-in/sign-in-again, Disconnect, risk-consent dialog, `DiscordLoginWebView` dialog) moved into Settings → Accounts' Discord row (`VrcaSettingsPage.AccountsSection`). Tab order: identity header → status banner → alerts. **Post-Phase-7 fixes (user feedback round)**: (1)
  **Real-time friends count** — `publishFriendsOnline()` counts a friend online when their `status` OR `location` is non-blank/non-"offline"; the WS `friend-online`/`friend-location` payloads don't always carry `user.status` (the user object is optional), so the old status-only predicate never moved the count on live events — it only changed on the REST friends reload at reconnect ("count only updates when I reopen the app"). (2) **Banner ≠ pfp**: `VrcUserPresence.profilePicUrl` is now the round `userIcon` and the new `bannerUrl` carries `profilePicOverride` (the wide profile banner); the identity card renders the banner as the CARD BACKGROUND (session-authed `AsyncImage` + black vertical-gradient scrim 0.45→0.72; the trailing View-Profile/Sign-out IconButtons get a 0.40-alpha black circle backing when a banner is present). No banner (no VRChat+) → plain card. The admin-side `fetchProfilePicUrl`/`refreshProfilePic`/post-2FA pic capture all prefer `userIcon` and only fall back to `profilePicOverride` — cropping the banner into the avatar circle was the "banner used as pfp" bug. (3) **Trust rank chip follows VRChat's real names+colors** (`trustBadge()`;
  VRChat's tag names are OFFSET from the displayed ranks, same mapping as VRCX): basic→"New User" blue 0xFF1778FF, known→"User" green 0xFF2BCF5C, trusted→"Known User" orange 0xFFFF7B42, veteran→"Trusted User" purple (lightened 0xFFB18FE4 for dark-bg readability), legend→"Veteran" yellow 0xFFFFD000, unknown→"Visitor" grey; "Legendary" deliberately excluded (it does not exist). Badge container = `color.copy(alpha=0.22f)` with colored label text. `VrchatPipelineService.prettyTrustRank` (rank-change notifications) uses the same corrected mapping. (4) **Notifications section defaults EXPANDED**; its expand state lives in the process-scoped `AlertSectionState.expanded` (same pattern as `StatusBannerState`) — persists across tab switches, resets to expanded only on a fresh process; a headless OEM revival has no UI on screen, so the reset is only ever visible on a genuine reopen, which is exactly the intended behavior.

- **Feature toggles live ONLY in Home's Quick Toggles.** The redundant per-feature enable switches were removed from the detail pages: the Pinned toggle and Cycle toggle in the Automations tab (`AutomationsPage.kt`), and the "Enable Now Playing block" toggle + the "Demo mode (testing)" toggle in the Media tab (`NowPlayingPage.kt`). The "Music demo mode" toggle in Settings → Interface and the demo toggle in the legacy `NowPlayingPage` (`LegacyPagesAndSettingsPage.kt`) were also removed. The `vm.setAfk/Cycle/SpotifyEnabledFlag` functions stay (driven by Quick Toggles); `spotifyDemoEnabled`/`setSpotifyDemoFlag` remain defined but now have no UI entry point (demo-track logic is effectively dormant). `NowPlayingPage` no longer takes `onPersistSpotifyEnabled`/`onPersistSpotifyDemo` params.

- Settings: Full page accessed via gear icon in top app bar. Contains Permissions, About, Help, and collapsible Debug section

- Admin: Full page accessed via gavel icon in top app bar (admin build only). Includes targeted APK push per user and release retraction.

### Settings page (`VrcaSettingsPage.kt`)

Grouped sections: **Chatbox display** (Invisible Chatbox Border toggle, description "Shrinks the chatbox background." + **"Time format" toggle** (label renamed from "24-hour time"; description "Change your time format to 12 or 24 hour mode." — `vm.time24h`/`setTime24hFlag` ← DataStore `time_format_24h`, default OFF = **12-hour with AM/PM** (`DateTimeFormatter "h:mm a"` with `Locale.US` for a stable uppercase marker) vs ON = `"HH:mm"`; consumed by `currentTimeString()` so it applies to the Time chatbox line, the preview, and `lastReportedTime`), **App** (version display + Battery Optimization request — promoted out of Permissions), **Permissions** (ALL permissions the app uses: Notifications (`ACTION_APP_NOTIFICATION_SETTINGS`), Notification Access, **Install updates** (`ACTION_MANAGE_UNKNOWN_APP_SOURCES` — in-app APK installs), Overlay), **About**, **Help** (collapsible FAQ rows via `HelpFaqRow`), **Debug** (collapsible). **The VRChat re-login takeover passes `onCancel` into `VrchatLoginScreen`** — Cancel renders INSIDE the login screen content (a `TextButton` above the disclaimer; the old top-bar Row placement clashed with the app bar).
  Same for the VRChat-tab takeover; onboarding passes no `onCancel` (hard gate, no cancel). Deliberately NO check-for-update button (a user could spam Firestore reads). Account/VRChat, Discord RPC, Notifications, and IP-slot sections were considered and rejected by the user.
