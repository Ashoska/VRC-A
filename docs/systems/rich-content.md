# Rich content engine (updates, announcements, What's New)

_Scope: RichDoc model, renderer, media store, admin RichDocEditor + uploads, announcements surface, video/GIF playback, device-feedback fixes._

### Rich Content engine (`com.vrca.richcontent` — Phase 1 of the Updates/Announcements/Status revamp)

Shared block-based document system that will power the Update popup, Settings "What's New", and the in-app Announcements list (one model + renderer + media store, so a new block type lights up everywhere). Status popup is a separate re-skin, not authored content. **Phase 1 shipped = the engine only; NOT yet wired into any surface** (that's Phase 2 = updates, Phase 4 = announcements). Four files, zero new dependencies (public APK unchanged — Coil already present, `VideoView` will be built-in, parser is ours). **All four compile clean on both variants.**

- **`RichDoc.kt`** (pure Kotlin + `org.json` — the codebase's JSON lib): `RichDoc(v, blocks)` where `RichBlock` is a sealed class — `Heading(text, color?)`, `Text(text)`, `Bullets(items)`, `Image(url)`, `Video(url, poster?)`, `Callout(tone /* info|warn|success */, text)`, `Divider`. Serialised to a JSON string stored in ONE Firestore field (`bodyDoc`) on announcement/release docs → single doc read; media (images/videos) live on GitHub/jsDelivr, never Firestore. `toJson()`/`parseRichDoc(json)` round-trip (parse is tolerant: returns null on blank/garbage/empty, skips unknown block `t` types for forward-compat with newer admin builds). `mediaUrls()` collects every image/video/poster URL in order (feeds the media-store reference set). `toPlainText()` flattens for legacy fields / collapsed-card previews (strips inline markup). **BACK-COMPAT is load-bearing**:
  `legacyDoc(text)` parses an existing plain `notes`/`text` string into blocks using the SAME rules the old `parseTosBlocks` used (numbered `^\d+\.` headers, `*`/`-` bullets grouped into one `Bullets` block, blank-line paragraphs, literal `[label](url)` markdown-link collapse) so old announcements/releases render with their original structure. **`resolveRichDoc(bodyDoc, legacyText) = parseRichDoc(bodyDoc) ?: legacyDoc(legacyText)`** is the accessor every render site uses — prefer the rich doc, fall back to legacy. (The old update system therefore keeps working on old app versions AND old docs; a forced update can still show no notes exactly as today by leaving `bodyDoc`/`notes` blank.)

- **`InlineMarkup.kt`** (Compose ui-text): `buildInlineAnnotated(raw, linkColor): AnnotatedString` — supports `**bold**`, `*italic*`, `[c=#RGB/#RRGGBB/#AARRGGBB]colored[/c]` (a toggle/stack scanner), and **auto-linkifies bare `https://` URLs** into clickable underlined primary-tinted spans tagged `"URL"` (trailing punctuation trimmed off the link). `AnnotatedString.urlAt(offset)` reads the tag on tap. `parseHexColor(hex)` (3/6/8-digit → `Color`). `stripInlineMarkup(s)` for previews. Pure (colors passed in) so it's unit-testable. **No button/link block — a raw URL in text just becomes tappable.**

- **`RichDocRenderer.kt`** (Compose + Coil): `RichDocRenderer(doc, modifier, mediaScope)` renders blocks as a responsive vertical `Column` (spacedBy 12dp) — **never a freeform/absolute canvas** (breaks across screen sizes). Heading = `titleMedium` in `block.color ?: primary`; Text/bullets/callout via a private `RichText` (uses **`ClickableText`** + `urlAt` + `LocalUriHandler` — the pre-1.7 clickable-link path, because this project is on **Compose BOM 2024.01.00 / ui-text ~1.6**, where the modern `LinkAnnotation.Url`/`withLink`/`TextLinkStyles` API does NOT exist; ClickableText is deprecated in foundation 1.7 but still compiles as a warning); Callout = tinted `Surface` (`accent.copy(alpha=0.14f)` + a 4dp accent bar; info→primary / warn→amber 0xFFFFB300 / success→green 0xFF4CAF50); Divider = `Divider` (NOT `HorizontalDivider` — M3 1.1.2 in this BOM has only `Divider`, the modern name is unresolved — a real compile catch). **Image** = full-width `AsyncImage` at intrinsic ratio, **local-file-first via `RichMediaStore`** (`model = cachedFile ?: url` so it renders from disk once cached, Coil network fallback meanwhile) with tap → pinch-zoom fullscreen `Dialog` (mirrors `TutorialImage`). **Video renders an INERT poster+play-glyph placeholder this phase** — real tap-to-play WITH AUDIO (built-in `VideoView`, single active player) lands in Phase 5.

- **`RichMediaStore.kt`** (modeled on `AlertImageStore` + `TutorialImageStore`): on-demand media cache at `filesDir/rich_media/`, SHA-1(url) key, `.part`-then-rename, **two scopes in separate subdirs** — `ann/` (**persistent, admin-controlled**: `gcAnnouncements(referencedUrls)` deletes any `ann/` file not in the active-announcements URL set → admin remove/swap culls it from user storage immediately) and `upd/` (**ephemeral, view-scoped**: `clearUpdateMedia()` wipes it on update-popup / What's-New close; patch-note TEXT stays cached elsewhere, only heavy media is transient). `ensureCached(url, scope)` is scope-LOCAL (a URL used by both an announcement and an update keeps two copies so `clearUpdateMedia` can never delete an announcement's media); `resolve(url)` reads across both scopes. No auth cookie (media is public jsDelivr/github). **Phase-3 rule (not yet built): admin uploads use a UNIQUE filename per upload (`<id>_<epochMillis>.<ext>`), never overwriting — jsDelivr caches hard, so a new upload = new URL = live edits appear instantly, and the old URL falls out of the reference set → auto-culled.**

**Phase 3 shipped = Admin builder (`RichDocEditor`) + GitHub image upload + rich Announcements AND Releases authoring** (`RichDocEditor.kt` new, `AnnouncementsTab.kt` rewritten, `ReleasesTab.kt` + `firestore.rules` edited; compiles clean both variants). **`RichDocEditor(blocks: SnapshotStateList<RichBlock>, githubPat)`** (`com.vrca.admin`) is the reusable block-list editor: per-block type-specific fields (heading text+hex color / text with `**bold** *italic* [c=#hex]` hint / bullets add-remove items / image URL + "Pick & upload" / video URL+poster / callout tone chips info·warn·success / divider), each block card has **move up / move down / duplicate / delete** controls (drag-and-drop is a deferred polish — reorder works via the arrows), an **Add block** horizontally-scrolling chip row, and a **live `RichDocRenderer` preview** (the same renderer users see). **Firestore cost = ZERO for the editor** (pure local state; media → GitHub).
  **`githubUploadImage(ctx, uri, pat)`** PUTs the picked image to the PUBLIC image-store repo (`Ashoska/VRC-A-Image-store`) via the GitHub **Contents API** with a **UNIQUE filename** (`rich/rich_<epochMillis>.<ext>`, never overwrite → jsDelivr cache-safe live edits) and returns the **jsDelivr** URL (`cdn.jsdelivr.net/gh/Ashoska/VRC-A-Image-store@main/rich/…`); it reuses the release **`BuildConfig.GITHUB_PAT`** (the PAT needs Contents:write on the image-store repo — **on failure it throws GitHub's own error text so a token/permission problem is diagnosable on-device**). **`AnnouncementsTab`** now authors a `RichDoc` (Title stays a plain field; the old Body textarea is replaced by `RichDocEditor`): Publish/Update writes `title` + `bodyDoc` (JSON) + `body` (plaintext flatten via `toPlainText()` for old clients/notification) in **ONE write**, then **optimistically updates the local list (zero re-read)** — respecting the "one write, minimal reads" mandate. **Edit** loads an announcement's `bodyDoc` (via `resolveRichDoc`, from the already-read row → zero extra read) back into the editor; **Copy** loads it as a new draft; a "RICH" pill marks rich announcements.
  `AnnouncementRow` gained `bodyDoc`; the 50-doc refresh reads it (same query). Announcements `create/update` rule is `if isOwner()` (no key restriction) so **no rule change was needed** for announcements. **`ReleasesTab`** keeps its plain `editNotes` (GitHub release body + legacy `notes`) and ADDS a `RichDocEditor` (`releaseBlocks`); publish writes `bodyDoc` (JSON) + `notes` (= `editNotes` or the rich doc's plaintext fallback) — one write. **`firestore.rules`: `bodyDoc` added to the `releases` `create/update` `hasOnly([...])` allowlist** (announcements needed none). So the client's Phase-2 `resolveRichDoc(bodyDoc, notes)` now has an admin-authored source for BOTH updates and announcements. (Deferred: drag-and-drop reordering, and per-video transcode/upload which is Phase 5.)

The background `VrchatPipelineService.attachAnnouncementsListener` still owns the off-screen NOTIFICATION. (Deferred: a nav-icon unread count badge — the per-card NEW dot ships now.)

**Phase 5 shipped = Video (playback with audio + admin transcode/upload)** (`RichDocRenderer.kt`, `RichDocEditor.kt`, `app/build.gradle`, two flavor source sets; compiles clean both variants). **Public playback (ZERO new deps)**: the `Video` block now renders `RichVideo` — poster + play button; tapping plays inline **with audio** via the built-in `android.widget.VideoView` (`AndroidView`). **Single active player** via a process-scoped `ActiveVideoState.playingKey` token (each card holds a `remember { Any() }` token; starting one sets the key so every other RichVideo drops back to its poster and releases via `AndroidView(onRelease = { stopPlayback() })`). **Admin transcode is flavor-scoped so the PUBLIC APK gains 0 dependencies**: `transcodeVideoForUpload(ctx, uri): File?` is defined in BOTH flavor source sets — `app/src/publicApp/.../VideoTranscode.kt` is a no-op stub returning null, `app/src/adminApp/.../VideoTranscode.kt` is the real **Media3 Transformer** transcode (HEVC/H.265 + AAC + ~4 Mbps bitrate cap via `DefaultEncoderFactory`/`VideoEncoderSettings`, `@OptIn(UnstableApi)` so the marker doesn't leak to the shared caller).
  **`androidx.media3:media3-transformer/common/effect:1.3.1` are added via `adminAppImplementation`** (admin APK only; the flavor is `adminApp`). The shared `RichDocEditor` Video block gained a **"Pick & upload"** button: it launches a `video/*` picker → `transcodeVideoForUpload` (admin compresses; public stub returns null → raw fallback) → a **19 MB size guard** (jsDelivr ~20 MB cap; over → error telling the admin to shorten or paste a URL) → `githubUploadVideoBytes` (the image uploader refactored into a shared `uploadBytesToImageStore(bytes, ext, pat)` reused by image + video, unique `.mp4` filename, jsDelivr URL). Zero Firestore cost (media on GitHub). URL-paste for video/poster still works as a fallback. (Refinement deferred: resolution downscale via `Presentation` — bitrate cap is the real size lever.)

**Post-testing fixes (round 2 — device feedback)**: (1) **Bold/italic now render via per-run PARAMETER-level styling** — a Samsung device silently DROPPED per-SPAN `fontWeight`/`fontStyle` (only span color rendered), so `RichText` was rewritten: `buildInlineRuns` produces a flat `List<InlineRun>` (bold/italic/color/url per run) and the renderer draws each run as its OWN `Text` with **parameter-level** `fontWeight`/`fontStyle`/`color` on `FontFamily.SansSerif` (a real bold/italic font), inside a `FlowRow`; `\n` splits into stacked rows. The old `buildInlineAnnotated`/`urlAt` AnnotatedString+SpanStyle path was removed. Links stay tappable (per-run `clickable`). Do NOT go back to SpanStyle weight/style — some system fonts ignore it. (2)
  **Streamed release-asset media upload** — media now uploads as raw-byte GitHub RELEASE ASSETS to an auto-managed `rich-media` release (`ensureMediaReleaseUploadUrl` caches the upload_url, reusing `githubCreateRelease`), replacing the base64 Contents API which inflated the file 33%, built a giant in-memory JSON, and did one blocking POST + a git commit per file — that's why uploads crawled and SATURATED the connection while APK pushes (the same streamed-asset path) were near-instant. Stored URLs are the release **download URLs** (`github.com/.../releases/download/rich-media/<file>`, CDN-backed; client caches locally then plays/loads from disk). `githubDeleteFileByUrl`/`githubSweepOrphans` now find + DELETE release assets by name/id. (3) **GIF is its OWN block** (`RichBlock.Gif`) — upload a `.gif` OR paste a direct GIF link (`media.giphy.com/….gif` etc.), rendered via the GIF-enabled `RichImage`. No Tenor/Giphy search picker: Google shut down the Tenor API (Jan 2026 deprecation, June 2026 shutdown, no new keys), Giphy went paid, and a picker would add a standing third-party dependency — so direct-link + upload only.

**Post-testing fixes (round 3 — device feedback, media playback)**: (1) **Video PLAYBACK is now Media3 ExoPlayer → TextureView, NOT `VideoView`** (`RichDocRenderer.kt` `RichVideo`, `app/build.gradle`). `VideoView` (and `PlayerView`) render into a `SurfaceView`, which punches a hole in the view hierarchy and z-orders BEHIND Compose content — so the video played as a **black box** in BOTH the admin editor preview AND the published announcement (same `RichVideo` either way, proving it was the player component, not the `AnimatedVisibility` context). The clip downloaded fine (`cached ~8 MB`) and re-encoding to H.264 didn't help, confirming a rendering issue. Fix: `androidx.media3:media3-exoplayer:1.3.1` added as a top-level **`implementation` (BOTH builds, ~1 MB to public APK)**; `RichVideo` creates an `ExoPlayer` (`remember(playUri)`, released via `DisposableEffect`) rendering into an `android.view.TextureView` (`exo.setVideoTextureView(tv)`) — a TextureView composites like a normal view (no surface hole). Aspect ratio tracked from `Player.Listener.onVideoSizeChanged` (`Modifier.aspectRatio`, coerced 0.5–2.5) so it isn't stretched; `STATE_ENDED` clears the single-active-player token;
  `onPlayerError` shows a clean "Couldn't play this video." **Did NOT add `media3-ui`/`PlayerView`** (also a SurfaceView + not cached offline). `@androidx.annotation.OptIn(UnstableApi)` on `RichVideo` (some Media3 markers). (2) **Admin transcode is H.264/AVC, not HEVC/H.265** (`app/src/adminApp/.../VideoTranscode.kt`, `setVideoMimeType(MimeTypes.VIDEO_H264)`) — HEVC decode isn't universal (a cached HEVC clip could download yet fail to decode), and at the same 4 Mbps bitrate cap file size is comparable (HEVC only buys quality-per-bit). (3) **`RichMediaStore.ensureCached` uses OkHttp** (`followRedirects`/`followSslRedirects`, 60s read / 120s call timeouts), not `HttpURLConnection` — GitHub release-download URLs 302-redirect cross-host to `objects.githubusercontent.com`, which `HttpURLConnection` didn't reliably follow, so videos never cached locally (images/GIFs masked it via Coil's own redirect-following URL fallback). (4) **GIFs animate inside the announcement card via a per-frame redraw** — a GIF (`RichImage(animate=true)`) runs a `withFrameMillis` ticker read INSIDE a `Modifier.drawWithContent { frameTick.intValue; drawContent() }`, forcing the draw phase to re-run each frame.
  Required because the announcement card wraps content in `AnimatedVisibility`, which stops forcing redraws once expanded, so Coil's `AnimatedImageDrawable` froze until an external redraw (touch/scroll) — the editor preview animated fine because it isn't inside an `AnimatedVisibility`. Ticker only runs while the GIF is composed (card expanded). Blank-URL image/video-poster blocks now early-return (no "Unable to create a fetcher" noise from unfilled editor blocks). (5) **Rich editor content + scroll survive the media picker** — `releaseBlocks` (`ReleasesTab`) and `targetedBlocks` (`UsersTab`) were plain `remember { mutableStateListOf() }`, so launching the image/video/gif file picker (which recreates the heavy admin Activity — the PROCESS survives, only the Activity is rebuilt, which is why the `AdminRuntime`-held APK pick survived but these didn't) reset them → the update-log content was LOST.
  **`rememberSaveable` was NOT sufficient**: on recreation `AdminScreen.sharedUsers` reset empty, so the selected-user DETAIL subtree (gated on the user being present) was DISPOSED for a frame past Compose's saved-state restoration window, dropping the saved blocks (and bouncing the admin to the top of the screen). **Fix = process-lifetime state in `AdminRuntime`** (same pattern as the APK pick): `AdminRuntime.editorBlocksFor(key)` / `editorNotesFor(key)` / `isEditorSeeded`+`markEditorSeeded` / `clearEditor(key)` hold the block list + plaintext notes + one-shot seeded flag keyed by editor id (`"release"` global, `"targeted:<docId>"` per user), cleared on publish. The picker `pendingImageIndex`/`pendingVideoIndex`/`pendingPosterIndex`/`pendingGifIndex` are `rememberSaveable` so the ActivityResult callback lands on the right block. **Scroll-to-top fix (two parts)**: (a)
  `AdminScreen.sharedUsers` is seeded SYNCHRONOUSLY from `UsersDirectoryCache.load(ctx)` (was `emptyList()`) so the directory is populated from frame one on recreation and the detail view is never disposed (zero extra Firestore reads — same on-disk cache the async loader already used; the full-fetch/incremental decision is unchanged); (b) both editors' scroll `Column`s use `rememberSaveable(saver = ScrollState.Saver)` (the detail one keyed by `docId`) so the position is restored. The detail 10s poll / watcher writes are untouched (still gated on `selectedDocId`+foreground, so leaving the detail still stops them). **Media UPLOADS also run on `AdminRuntime.scope`** (`AdminRuntime.uploadMediaBlock` + `uploadingTagsState`/`uploadErrorsState`, `RichDocEditor(editorKey=…)`): the upload previously ran on the editor's `rememberCoroutineScope`, which the picker's Activity recreation CANCELLED mid-upload → the block never got its URL ("I pick a file but it doesn't appear as added").
  Now the upload (image/gif/poster + the video transcode+size-guard) runs on the process scope and writes the URL straight into the process-lifetime block list, so it completes across the recreation; progress/errors are read back from AdminRuntime StateFlows keyed `"<editorKey>#<index>"`. All THREE editors (releases `"release"`, targeted `"targeted:<docId>"`, announcements `"announcement"`) share this. **Update popup is FULL-SCREEN** (`UpdateDialog`, `VrcaApp.kt`): `Dialog(usePlatformDefaultWidth=false)` + a `fillMaxSize().padding(10.dp)` card; the rich patch-notes `Surface` takes `weight(1f)` (fills all space between header and the pinned Download button, was capped at 50% screen height), with an iconed `headlineSmall` header + version pill. **Retract clears the popup live**: retracting a release (normal or targeted) DELETES the `releases/*` doc; the user's `releases/latest` + `releases/{deviceHash}` listeners now, on `!snap.exists()`, drop the `UpdateDialog` (and lift the forced-OSC gate) when it's currently showing THAT source's version (tracked via `lastGlobalCode`/`lastTargetedCode`, zero extra reads) instead of leaving a retracted update on screen until restart.
