# Chatbox sending + automations content

_Scope: OSC Start/Stop gate, toggles + auto-restore, sub-lines codec, cycle lines/shuffle/tokens, presets auto-save, manual send, cycle sender, invisible border, rate limit, naming, removed features._

- **Chatbox sub-lines (multi-row Pinned / Cycle — `app/SubLineCodec.kt`)**: the Pinned message and each Cycle line can hold up to **3 sub-lines**, each rendering as its own VRChat chatbox ROW. A sub-line is `ChatboxSubLine(text, hidden)`; the list order is the row order; a `hidden` sub-line stays in the editor (and syncs) but is NOT sent. **The hide/order/hidden-text state rides the EXISTING synced string fields** (`afkMessage` for Pinned, each `\n`-delimited slide of `cycleLinesText` for Cycle) via `SubLineCodec` — **ZERO new Firestore fields, zero extra reads/writes** — so the admin, decoding the same format, sees + can moderate every row (hidden included). **Encoding**: a lone VISIBLE sub-line encodes as PLAIN text (no markers → byte-for-byte backward compatible with old readers and the single-row case); otherwise `SENTINEL() + sub0 + SEP() + sub1 + …` where a hidden sub-line's text is prefixed `HIDDEN()`. An encoded slide never contains `\n`, so `cycleLinesText`'s slide-level `\n` split / cross-device parsing are unaffected. `sanitize()` strips those control chars (and the reserved ` `) from user input.
  **`renderVisible(stored)`** (visible, non-blank rows joined by real `\n`) is the ONLY thing sent to VRChat — hidden rows cost nothing against the 144 budget; `visibleRowCount()` feeds the 9-line budget (`limitWithPriority` now counts ROWS, `text.count('\n')+1`, not blocks). **Admin readable round-trip** (`toAdminText`/`fromAdminText`, cycle variants `toAdminCycleText`/`fromAdminCycleText`): the admin text boxes show rows joined by `" ⏎ "` with hidden rows tagged `"⊘"` and re-encode on save, so the raw control-char form never appears in admin UI. **Phase 1 shipped = Pinned**: `VrcaViewModel.pinnedSubLines()`/`setPinnedSubLineText`/`setPinnedSubLineHidden`/`addPinnedSubLine`/`removePinnedSubLine`/`movePinnedSubLine` all re-encode into `afkMessage` via `updateAfkText` (so presets ride along for free — `afkPreset1-3` store the encoded value; sync writes the RAW `afkPresetTexts[i]`, NOT `getAfkPresetPreview` which returns a rendered preview).
  The Pinned editor (`AutomationsPage.kt`) is a reusable **`SubLineEditor`/`SubLineRow`**: the **MAIN line (row 0) shows normally and its number badge / chevron expands** to reveal up to 2 **small, indented, dimmer nested sub-line rows** (they must look like sub-lines, not standalone lines — per user feedback) each with its own hide (eye) / char meter / overflow (move up/down + delete), plus an indented "Add row" (≤3) and the **"up to 3 chatbox lines" caption that only shows while expanded** (the old always-visible "Message rows" header was removed). The main row's number badge = expand (NOT hide — the main line has no eye; hiding is a sub-line concept); collapsed it shows a "+N" chip when sub-lines exist. Expand state is a page-scoped `pinnedExpanded` `remember` (sub-lines hidden until the line is selected). The combined total `CharBudgetMeter` renders only when `visibleRowCount > 1` (a single row's per-row meter already IS the total). `pinnedSubs` is snapshotted in PAGE scope + sub-rows `key(i, hidden)`-wrapped (same AnimatedVisibility-skip fix as the cycle mute rows). `buildCombinedText` sends `resolveTokens(renderVisible(afkMessage))`.
  **Phase 2 shipped = Cycle**: each cycle slide is now sub-line encoded in `cycleLines[i]` (same codec). `activeCycleLines()` returns `SubLineCodec.renderVisible(cycleLines[i])` per active slide; `cycleActiveRawIndex`/preset previews/`hasVisible` all decode. VM ops `cycleSlideSubLines`/`setCycleSubLineText`/`setCycleSubLineHidden`/`addCycleSubLine`/`removeCycleSubLine`/`moveCycleSubLine` re-encode into `cycleLines[slide]` via `persistCycleLinesPreserve` (presets + sync ride along). The editor reuses `CycleLineRow` as the MAIN line (sub-line 0) with its **number badge repurposed from mute → EXPAND** (mute moved to the eye, which cycle already had; overflow still moves/duplicates/deletes the whole SLIDE) + a trailing chevron/"+N"; expanding renders the compact `SubLineRow`s for sub-lines 1.. + Add row + a per-slide total. `cycleLineFields` is now keyed `"slide:sub"`, seeded from decoded sub-lines; `cycleSubs` (decoded per slide) is snapshotted in PAGE scope for the AnimatedVisibility-skip fix, and per-slide expand state lives in a `cycleExpanded` map.

- **Cycle line system (revamp + features)** (`AutomationsPage.kt` `CycleLineRow` + `VrcaViewModel`): line cap raised **10 → 20** (`VrcaViewModel.MAX_CYCLE_LINES`). Each line is a slim bordered `Surface` (~44dp) on `BasicTextField` with: an inline **number badge that doubles as the mute toggle** (dims when muted) + a `Visibility`/`VisibilityOff` mute icon, an **always-on** per-line `CharBudgetMeter`, and a `MoreVert` **overflow menu** (Move up / Move down / Duplicate / Delete). The line currently being SENT is highlighted live (primary tint + border) via a 1s ticker reading `vm.cycleActiveRawIndex()`. **New VM capabilities**: per-line mute (`cycleLineEnabled` — a `mutableStateListOf<Boolean>` kept index-aligned with `cycleLines`; LOCAL-only, persisted as a `1`/`0` CSV in DataStore `cycle_line_enabled`, NOT synced to Firestore — a muted line stays in the editor + the synced `cycleLinesText` but the sender skips it); `duplicateCycleLine`/`moveCycleLine`/`setCycleLineEnabled`;
  **shuffle** (`cycleShuffle` / `setCycleShuffleFlag`, DataStore `cycle_shuffle`, local-only) — random rotation via `nextCyclePos()` with a **no-repeat window** (`shuffleWindow(activeSize)`: how many recently-played positions to avoid before a line can recur — `1` for <5 active lines (just no immediate repeat), then ramps by linear interpolation between anchors **5→3, 10→5, 15→8, 20→14** (clamped above 20), so more lines enforce more variety; the window is computed over the **active** line count — blank AND muted lines are excluded by `activeCycleLines()`, so empty slots never count); **dynamic tokens** resolved live at send/preview time by the PUBLIC `resolveTokens()` (renamed from `resolveCycleTokens`) — `{time}` (Time-line string), `{song}` ("Artist - Title" now playing), `{world}` (VRChat world name), `{players}` (instance "n/cap"). **Tokens work in BOTH Pinned and Cycle** — `buildCombinedText` runs the `afkLine` through `resolveTokens` too. The sender (`startCycle`) + preview (`currentCycleLinePreview`) + idle ticker (`tickCyclePreviewOnly`) all walk `activeCycleLines()` (non-blank, non-muted, capped) and resolve tokens.
  The **char meter counts the RESOLVED length** (`vm.resolveTokens(text).length`) in both editors, so a `{world}` shows the actual world name's character cost, not the literal `{world}`. The hint line under both editors reads "Currently experimenting, feel free to try by putting these tags into your pinned and cycle message: {time} {song} {world} {players}" (shared `TokensHint()`). `setCycleLinesFromTextPreserve` is change-aware (an echo of our own `saveCycleMessages` keeps the local mute/shuffle state; only a genuine line-set change resets mute). Cycle speed chips (2s/5s/10s/20s/40s) unchanged. **Eye/mute responsiveness (hard-won — SIX prior attempts failed)**: the mute flags are snapshotted in the PAGE scope (`cycleEnabledFlags = vm.cycleLineEnabled.toList()`) and each `CycleLineRow` is wrapped in **`key(idx, lineEn)`** so a mute toggle forces Compose to recreate the row outright.
  Reading the state inside the `CompactSectionCard` content lambda, passing a provider lambda, or passing a changed plain Boolean WITHOUT the key() all failed on-device — the `AnimatedVisibility` content slot skipped the rows even when their params changed (the header summary, read in page scope, updated instantly the whole time). Do not remove the key() wrapper. **Focus-expand**: a focused cycle line field flips `singleLine=false`/`maxLines=6` (via `onFocusChanged`) so a long line wraps and is fully visible while typing, collapsing back to one line on blur. **Cursor-teleport fix (Pinned + Cycle editors)**: the fields are local `TextFieldValue` maps (`cycleLineFields` keyed `"slide:sub"`, `pinnedFields` keyed by index) synced FROM the VM via `syncCycleLineFieldsFromVm`/`syncPinnedFieldsFromVm`. The old sync rebuilt `cycleLineFields[k] = TextFieldValue(s.text)` whenever the round-tripped text differed — and `TextFieldValue(text)` defaults its selection to `TextRange.Zero` (the FRONT), so a keystroke's own VM echo yanked the cursor to position 0 mid-typing (tester: "cursor teleports to the front/randomly when typing or deleting fast"). Two guards:
  (1) a shared `focusedFieldKey` (`"c:$slide:$sub"` / `"p:$idx"`, set by each field's `onFocusChanged` → `onFieldFocus`, threaded through `CycleLineRow`/`SubLineRow`/`SubLineEditor` `onFocusChange` params) makes the sync SKIP the field the user is actively editing — its own echo can never clobber the live cursor; external changes (preset load, admin edit, cross-device) apply on blur. (2) `reseedField(existing, text)` PRESERVES the cursor (clamped) instead of resetting to `TextRange.Zero`, and returns the same reference when text is unchanged (no no-op state write) — the fallback for any non-focused re-seed. Manual Send (`vm.messageText`) already preserves the cursor (only scroll-mode forces end, intentional); admin fields use plain local `String` state (synchronous, unaffected).

- **Preset auto-save model (Pinned + Cycle)** (`VrcaViewModel` `selectedAfkPreset`/`selectedCyclePreset` + `AutomationsPage`): the SELECTED slot is the auto-save target — editing the Pinned text / cycle lines writes straight into the selected slot, so **switching slots IS the only "save" (no manual save button)**. **Slot 0 = NOTHING selected is the DEFAULT (DataStore `selected_afk_preset`/`selected_cycle_preset` default 0)** — `autoSaveSelectedAfkPreset` (`if (selectedAfkPreset !in 1..3) return`) and `autoSaveSelectedCyclePreset` (`if (selectedCyclePreset !in 1..5) return`) NO-OP when nothing is selected, so editing touches NO preset until the user deliberately taps a slot. **This is the backward-compat guarantee**: existing users (no DataStore key → 0) never have a saved preset clobbered by editing; the old unsafe default of 1 would overwrite slot 1 on the first edit.
  **Slot-0 data-loss migration (`migrateLiveContentIntoPresetSlot`, one-shot via DataStore `preset_seed_migrated`)**: slot 0 protects presets from EDITS but not from SELECTS — a pre-update user's live Pinned message / cycle lines are saved in NO slot, so their first tap on a preset chip loaded that slot over the live editor and silently destroyed their content. On VM init (after the initial DataStore load, before `initialDataLoaded`), the migration parks the live content in a slot once: prefer a slot already holding identical content (select it, no write), else the first EMPTY slot (save + select). All-slots-full-with-distinct-content leaves slot 0 and changes nothing (never clobber a deliberate save — accepted edge). Selecting during migration does NOT reload the editor (content is identical by construction). Fresh installs just get their default message parked in slot 1 — harmless.
  **Stale preset chips/peek fix (`AutomationsPage`)**: preset previews + the selected slot are snapshotted in the PAGE scope (`afkPresetPreviews`/`cyclePresetPreviews` Lists) — reads inside a `CompactSectionCard` content lambda don't reliably retrigger its `AnimatedVisibility` (same class of bug as the cycle-mute rows), so the auto-save writing into the selected slot left the chips and long-press peek stale until the tab was re-entered. Chips are wrapped in `key(slot, preview, equipped)` to force the repaint through, and `onPeek` reads the content FRESH from the VM at press time instead of using the composition-captured value. `updateAfkText` → `autoSaveSelectedAfkPreset`; every cycle content edit (`persistCycleLinesPreserve`) → `autoSaveSelectedCyclePreset`. **Per-preset hide state (`cycle_pN_enabled`)**: each cycle preset stores its OWN per-line mute CSV (aligned to the preset's NON-EMPTY saved lines, so indices survive the empty-line drop in `messages`) via `cyclePresetEnabled` + the new `enabledCsv` param on `saveCyclePresetN`.
  This fixed "presets don't save hidden lines" — the hide state used to live ONLY in the global `cycle_line_enabled` CSV, which `setCycleLinesFromTextPreserve` reset to all-visible on every preset load, so a preset never remembered which lines were muted. **`setCycleLineEnabled` (the mute toggle) now DOES auto-save the selected preset** (`autoSaveSelectedCyclePreset()`, no-op at slot 0) — reversing the earlier "mute toggles don't auto-save" design, which was the root cause. `selectCyclePreset` restores the slot's hide CSV after loading its lines (a BLANK CSV — legacy presets saved before this feature — explicitly resets to all-visible so a switch between identical-line presets can't inherit the prior slot's mute). `saveCyclePreset(slot, lines)` compat helper and the cross-device/admin apply lambdas pass no `enabledCsv` (defaults to "" = all-visible; the CSV is local-only, never synced to Firestore). `selectAfkPreset(slot)`/`selectCyclePreset(slot)` record the new selection (1..N) and load that slot's content into the live editor (loads, never clears). The preset chips highlight by `slot == vm.selectedAfkPreset/selectedCyclePreset` (no content-match; nothing highlighted at slot 0).
  The long-press peek dialog is view-only now (Close + "Switch to this preset"); the "Save current here" button is gone. The old `saveAfkPreset`/`saveCyclePreset`/`loadAfkPreset`/`loadCyclePreset` helpers are now unused by the UI (kept for compat).

### Chatbox Rate Limit

VRChat's chatbox update limit is 0.5 seconds (`SEND_FLOOR_MS = 500L`). Music refresh is locked at 1 second (`MUSIC_REFRESH_SECONDS_LOCKED = 1`).

### Cycle sender reads LIVE lines (stale-snapshot fix)

`startCycle()`'s loop re-reads `cycleLines` (trimmed/filtered/take(10)) **every tick** — it must NOT iterate a list captured at launch. The old captured-snapshot loop caused: editing a cycle line mid-send showed the new text (preview + the music loop's null-override rebuilds read live state) but flashed the PRE-EDIT text at each rotation boundary (only the cycle tick was stale), until a Stop/Start re-captured the list. Empty-mid-send is handled (renders without a cycle line via `forceClearIfAllOff`, keeps looping so re-adding a line resumes); `cycleIndex` is clamped when lines shrink. **`cycleIndex` advances AFTER the interval delay, not right after the send** — during the wait it must keep pointing at the on-screen line so `currentCycleLinePreview()` (preview + other sender loops' null-override rebuilds) agrees with what the tick sent; the old post-send increment made the preview point one line ahead for the whole interval (invisible in steady state as a pure phase shift, visible as a disagreement the moment a line's content changed). Edits while sending surface at the next rotation tick by design (no per-keystroke OSC push — typing would spam partial strings to VRChat).

### Manual Send takeover + modes (`HomePage.kt` Manual Send card, `VrcaViewModel`)

Sending a manual message **pauses the automated chatbox (Pinned/Cycle/Music/Time) for 20s** (`MANUAL_HOLD_MS`, bumped from 10s) so people can read it. **On hold expiry the input field is CLEARED** (both the Instant-mode `scheduleManualRevert` and the Live-loop expiry branch set `messageText = ""`) so a fresh manual send starts empty instead of the stale text lingering ("retyping reshows old text"). **The field is kept in view while typing** via a `BringIntoViewRequester` (`manualBring`) on the `OutlinedTextField` + a `LaunchedEffect(messageText.text, focused)` that `bringIntoView()`s after a 60ms relayout delay — the live preview above the field grows as you type and would otherwise scroll the input line out of view (tester-reported). Below, "10s"/"the 10s hold" refer to this same now-20s window. **Revert respects the `oscSending` master gate (`revertToNormalChatbox`)**:
  `rebuildAndMaybeSendCombined(forceSend=true)` builds from the feature TOGGLES, not `oscSending`, so every normal caller guards it with `if (oscSending)` — but the manual-revert paths did NOT, so sending a manual message while NOT Started (oscSending=false) and letting the hold expire fired ONE automated send if any toggle was on ("using manual message when OSC isn't sending makes automation send when the timer finishes"). All revert/clear paths (`scheduleManualRevert` expiry, both Live-loop expiry branches, `clearManual`, and the `setManualLiveModeFlag`-off path) now go through `revertToNormalChatbox(local)`: when `oscSending` it resumes automation (`rebuildAndMaybeSendCombined`), when NOT it just `clearChatbox`es the one-off manual message and restores the preview to `buildCombinedText` — never transmitting automated content. Manual send itself still bypasses the gate (one-off always allowed) and starts no loops. The pause is enforced at the single automated chokepoint: `rebuildAndMaybeSendCombined` early-returns while `manualHoldActive()` (`now < manualHoldUntilMs`), setting the Home preview to the manual text.
  **It does NOT pause the sender loops themselves** — the cycle/music/keepalive `while` loops keep ticking (cycle keeps advancing `cycleIndex` + its timer in the background), only their OUTPUT is suppressed, so when the 10s expires the automation resumes from wherever it now is with no reset. A manual send is NEVER gated (it goes straight through `VrcaOsc.sendMessage`), so the user can send again mid-window and it re-arms the 10s. `scheduleManualRevert()` restores the normal chatbox (`rebuildAndMaybeSendCombined(forceClearIfAllOff=true)` + typing off) once the hold expires — this is what "goes back to normal" even when no automated loop is running (OSC off). Two Manual Send controls (compact segmented toggle + a Live-only toggle, DataStore `manual_live_mode`/`manual_scroll`, local-only): **Instant** (default — type + Send, one-shot, blocked when over the 144/142 budget via `manualCharBudget()`; the Send button disables + the field shows an error counter) and **Live** (the chatbox updates every 0.5s as you type via `startManualLiveLoop`, with a `/chatbox/typing` indicator; each change re-arms the 10s hold so the message stays up 10s after the LAST keystroke, then reverts).
  **The typing indicator is suppressed while the invisible/minimal-background chatbox is ON** — the combination glitches VRChat's in-game UI, so the `VrcaOsc.typing` setter gates on `minimalBackground` at the chokepoint (`effective = value && !minimalBackground`; a clear still passes through). Only manual-send paths set `typing`; the automated combined senders never do. **Scroll** (Live-only) shows the newest 4 VRChat chatbox lines (`MANUAL_SCROLL_LINES`) via `formatManualScroll(text, budget)`. **It WRAPS the text itself** (`wrapToVisualLines` — greedy word-wrap by estimated proportional width `MANUAL_SCROLL_WIDTH=26f`, a touch narrower than VRChat's ~30-unit wrap so VRChat never re-wraps our lines into a 5th; honors explicit `\n`, hard-splits an over-long unbroken word) then keeps the newest ≤4 wrapped lines within the char budget, joined with `\n` to lock the breaks — older lines scroll off the top. This fixed the reported bug where splitting only on `\n` treated a long unbroken message as ONE line and trimmed CHARACTERS off the front (`takeLast(budget)`) instead of dropping whole lines. `manualCharWidth` estimates glyph width (caps/wide glyphs wrap sooner).
  The over-budget counter is NOT error-colored in Live mode (Scroll handles overflow by design). **The in-app field RENDERS EXACTLY AS VRChat wraps it in Live+Scroll (WYSIWYG)** — `onMessageTextChange` (scroll branch) collapses the field to flowing text (`replace("\n"," ")`) and sets it to `formatManualScroll(...)` (the wrapped, newest-4-lines-within-budget string it also SENDS), cursor forced to the end. This REPLACED `trimManualToWindow` (deleted): the old approach kept the field as raw text and only trimmed off-window lines, but the in-app box is WIDER than VRChat's chatbox, so a message that wrapped to 3 lines in VRChat showed as 2 in the box — the field's lines didn't match the chatbox, and a line scrolling off made the field jump / typing feel off (tester-reported "not smooth to type in"). Now field == what's sent == what VRChat renders (same wrap, same 4 lines), so the visible lines always agree and the field never grows past the char budget (`formatManualScroll` windows the total ≤ budget). Newlines collapse to spaces while Scroll is on (a scrolling ticker is one flowing line in VRChat), so manual line breaks aren't kept in that mode.
  The **Clear** button is an `OutlinedButton` (was a bare `TextButton` that didn't sit right next to the filled Send); the Scroll toggle description is "Scroll to the 4 newest lines." A **Clear** button (`clearManual()`) drops the hold, clears the field + chatbox, and restores the normal chatbox. **The live loop re-pushes the CURRENT field text every 0.5s for the ENTIRE hold window — even while the user is paused — not only on change** (`startManualLiveLoop`): a genuine edit (re)arms the 10s hold and shows the `/chatbox/typing` dots (`typingOn` flag, dots drop when paused), while every tick still sends the current (scroll-formatted) text, so a keystroke that lands between ticks during fast typing is always reflected within 0.5s and the final bit is never stranded (tester-reported "the last bit doesn't send when typing fast"). Identical re-sends are cheap and keep the chatbox message fresh until the revert. It idles (breaks) only once the field is unchanged AND the 10s hold has elapsed (the revert restored the normal chatbox); a keystroke restarts it. The legacy `messengerUiState.isRealtimeMsg` path was replaced by `manualLiveMode` in `onMessageTextChange` (the overlay + legacy conversation surfaces now share the same Live/hold behaviour).

### Voice-to-text dictation (Manual Send mic — HEADSET-ONLY, offline Vosk STT)

Hands-free dictation into the Manual Send field — built flagship-first for **mutes to communicate without speaking aloud** (the user's framing), and for anyone who finds typing in-headset slow. **It is headset-only**: the engine is backed by the Vosk offline recognizer, which is a `headsetAppImplementation` dependency (`com.alphacephei:vosk-android:0.3.47` in `app/build.gradle`) — so the native lib is NOT on the public/admin classpath and the whole affordance is HIDDEN there. **Works on Quest**, which has no Google `SpeechRecognizer`; fully on-device, so no network/API cost after a one-time model download.
- **`com.vrca.speech.SpeechToText`** is a flavor-stub `object` (same pattern as `VideoTranscode`): the REAL engine lives in `app/src/headsetApp/kotlin/com/vrca/speech/SpeechToText.kt` (`SUPPORTED = true`); `app/src/publicApp/` + `app/src/adminApp/` hold byte-compatible STUBS (`SUPPORTED = false`, `start()` returns false, `modelReady()` false). All three share the identical signature: `const val SUPPORTED`, `interface Listener { onPartial/onFinal/onError }`, `isListening()`, `modelReady(ctx)`, `downloadModel(ctx, onProgress, onDone)`, `start(ctx, listener): Boolean`, `stop()`.
- **Model**: Vosk small English (~40 MB), downloaded on demand from `alphacephei.com/vosk/models/vosk-model-small-en-us-0.15.zip` — NEVER bundled in the APK. `downloadModel` fetches on a background thread into `cacheDir`, then `unzipFlattened` (drops the archive's top-level dir) into `filesDir/vosk-model`; `modelReady` = the dir has `am/` + `conf/`. `onProgress` is 0..100 (95% = download, 96%+ = unzip).
- **Engine (headset)**: `start()` spins a daemon thread — `Model(dir)` + `Recognizer(model, 16000f)` + an `AudioRecord` (`VOICE_RECOGNITION` source, 16 kHz mono PCM16) read loop; `acceptWaveForm` → `onFinal(textOf(result))`, else `onPartial(textOf(partialResult))`. The recognizer + model + `AudioRecord` live in RAM ONLY while listening and are released in `finally`, so **idle cost is zero**. `stop()` flips the `@Volatile running` flag + interrupts the thread. Results are delivered ON the worker thread — the UI hops to main itself.
- **VM wiring** (`VrcaViewModel`, main-source, shared): `speechSupported` (= `SpeechToText.SUPPORTED`), `speechModelReady`/`speechListening`/`speechDownloading`/`speechDownloadPct`/`speechError` (`mutableStateOf`, `private set`), private `speechCommitted` (text committed by FINAL utterances). `startDictation()` FORCES `setManualLiveModeFlag(true)` + `setManualScrollFlag(true)` (so the transcript streams AND scrolls), seeds `speechCommitted` from the current field, then `SpeechToText.start` with a Listener that marshals every callback to `viewModelScope.launch(Dispatchers.Main)`: `onPartial` → `applySpeechTranscript(partial)`; `onFinal` → fold into `speechCommitted` + `applySpeechTranscript("")`; `onError` → set `speechError` + stop. `applySpeechTranscript(livePartial)` = `onMessageTextChange(TextFieldValue(committed + " " + partial, cursor-at-end))` — so the growing transcript rides the SAME Live+Scroll path typing uses, and **a long dictation scrolls the newest lines within the 144-char chatbox budget instead of being cut off** (the user's explicit requirement). `startDictation` kicks `downloadSpeechModel()` and returns if the model isn't ready yet. `stopDictation()` = `SpeechToText.stop()` + clear `speechListening`.
- **UI** (`HomePage.kt` `SpeechDictationRow`, called inside `ManualSendCard` under the Scroll toggle): `if (!vm.speechSupported) return` hides it on non-headset. A tonal `Surface` with a label/sub-label + a trailing control that switches on state — downloading → "Downloading voice model… N%" (text-only, no indicator import); model-not-ready → "Speak to type" + a **Download** button; ready+idle → "Tap the mic to speak" + a **mic** `IconButton`; listening → "Listening… tap to stop" + a **stop** `IconButton` (error-tinted). The mic button requests `RECORD_AUDIO` via `rememberLauncherForActivityResult(RequestPermission())` when not granted (`ctx.checkSelfPermission` idiom, matching Onboarding/Settings), else calls `startDictation()`. A `DisposableEffect` `stopDictation()`s if the row leaves composition while listening; `LaunchedEffect(Unit)` refreshes `speechModelReady` on entry. `speechError` renders under the row in error color.
- **Permission**: `RECORD_AUDIO` is declared in the **headset manifest ONLY** (`app/src/headsetApp/AndroidManifest.xml`) — foreground-only (we record while the user is actively dictating on screen), so NO `FOREGROUND_SERVICE_MICROPHONE`; runtime-requested. The public/admin manifests never request it.

### Cycle resume across Start/Stop (no snap-back to line 1)

`startCycle()` used to hard-reset `cycleIndex = 0` and show position 0 on the first tick, so every Start/Stop (and toggle off/on) restarted the cycle at line 1. It now captures `val resumePos = cycleIndex` (preserved by `stopCycle`, and kept advancing during a manual-send takeover) and the first tick shows `resumePos.coerceIn(0, live.size-1)` — the cycle continues from where it left off. `recentCyclePicks` is still cleared on start (shuffle no-repeat window doesn't persist across stop, acceptable).

### Invisible Chatbox Border ("skinny bubble" trick)

A display preference (user-facing name "Invisible Chatbox Border"; UI = a toggle in Settings → "Chatbox display" PLUS an unlabeled eye `IconButton` on the Home preview card next to `SendStatusChip` — deliberately no text/explanation, the preview's reaction IS the explanation; the Home preview simulates the state: full `surfaceVariant` bubble when off, floating text over a tiny 44×16dp pill when on) that appends U+0003 (END OF TEXT) + U+001F (UNIT SEPARATOR) to every outgoing `/chatbox/input` payload — the same undocumented trick VRCOSC ("Use Minimal Background") and MagicChatbox (`BlankEgg`) use. The control chars corrupt VRChat's bubble text-bounds measurement, collapsing the background to its minimum pill while the text renders normally (full removal is impossible — the pill is the client's minimum background, rendered on other players' clients). Implementation:
  `VrcaOsc.minimalBackground` (`@Volatile`, like `blocked`) + `withMinimalBackground(text)` applied in `sendMessage`/`sendRealtimeMessage` — caps content at 142 then appends, so the suffix can never be trimmed by the 144 limit; blank text is left blank (a chatbox CLEAR must stay a truly empty payload or an empty mini-bubble would linger in-game). `buildCombinedText` shrinks the builder budget to `VRC_MAX_CHARS - MINIMAL_BG_RESERVED_CHARS` (142) when ON so the preview matches what fits; OFF returns the 2 chars to content. The suffix is added ONLY at the OSC chokepoint — never in `combinedPreviewText`, conversation history, or Firestore. State: `VrcaViewModel.minimalChatboxBg` + `setMinimalChatboxBgFlag()` (the `Flag` suffix avoids the JVM setter clash, same as the feature toggles), persisted via DataStore key `minimal_chatbox_bg` like the notification toggles (survives close/swipe/restart; NOT a sender toggle — independent of `oscSending`/`FeatureSessionStore`, not synced to Firestore, applies to manual conversation sends too). ### UI Naming

- The "AFK" feature is renamed to "Pinned" in all user-facing strings. Internal variable/key names (`afkEnabled`, `afkMessage`, etc.) remain unchanged for backwards compatibility with DataStore and Firestore.

- Default presets use "Away" instead of "AFK" (e.g., "Away - grabbing water").

### Removed Features (do not re-add)

- **Divider system**: Previously allowed inserting text dividers between chatbox components. Fully removed from UI, ViewModel, DataStore, and message construction.

- **Preset naming**: Custom names for pinned/cycle presets. Removed from ViewModel, AdminScreen, DataStore, and Firestore sync. Presets now use generic "Preset 1/2/3..." labels.

- **Redundant action buttons**: Start/stop buttons in Cycle, pin/unpin + send once in Pinned, start/stop + test in Music — all removed since toggles handle activation.

### Toggle Persistence

Feature toggles (`afkEnabled`, `spotifyEnabled`, `cycleEnabled`, `timeEnabled`) survive Android process death (memory pressure) via `SavedStateHandle`, and survive Activity destruction because the runtime `VrcaViewModel` is now **app-scoped** (owned by `VrcaApplication`'s `ViewModelStore`, not the Activity's — see "Background Survival"). Content (messages, intervals, presets) DOES persist via DataStore as normal. Admin can still flip toggles in real-time via the Firestore snapshot listener, which writes directly to ViewModel state (and SavedStateHandle) without touching DataStore.

**OSC send gate (Start/Stop) — toggles configure WHAT, Start gates WHEN**: A master `VrcaViewModel.oscSending` boolean decides whether the enabled toggles actually transmit over OSC. **Toggling a feature no longer auto-starts sending** — flipping `afkEnabled`/`cycleEnabled`/`spotifyEnabled`/`timeEnabled` while `oscSending == false` only updates the local preview and persists the config; no OSC leaves the device and the VRChat chatbox is untouched (this lets the user set up their preview first). `startSending()` (Home "Start sending" button) flips `oscSending` true and launches the sender loops (`startAfkSender`/`startCycle`/`startNowPlayingSender` + `manageKeepaliveLoop`) for whatever toggles are on; each starter early-returns unless `oscSending && <its toggle>`, and every sender `while` loop also checks `oscSending` so the master gate hard-stops them. `stopSending()` (Home "Stop sending" button, replaces the old red **KILL**) flips `oscSending` false, stops all sender loops, and clears the VRChat chatbox **WITHOUT untoggling any feature** — so pressing Start again resumes exactly what was configured. **Auto-restore after an OS kill (`FeatureSessionStore`)**: A deliberate **swipe** still starts clean (toggles OFF, not sending), but an **OS-initiated process kill** (memory pressure / Doze / OEM killer) is made invisible — the chatbox resumes on its own **only if the user was actually sending**. `FeatureSessionStore` (`com.vrca.app`, backed by the `vrca_remote` prefs file) persists the active toggle set **plus the `sending` gate** on every toggle/Start/Stop change and **arms** restore. `VrcaViewModel.restoreFeatureSession()` runs once after initial content load: it re-applies the toggle CONFIG directly (so the preview reflects what was set up), then resumes OSC sending via `startSending()` **only when the persisted `sending` was true AND something was enabled** — toggles configured but never started come back idle (no transmission). `AppShutdown.onTaskSwiped()` calls `FeatureSessionStore.disarm()` so a real swipe (the only deliberate stop) is NOT restored — an OS kill never runs `onTaskSwiped`, so it stays armed. This is the per-session source of truth for "was this stop deliberate?"; do not key restore on the `manual_kill_at` timestamp (it persists across sessions and can't distinguish a stale prior swipe from a fresh OS kill).
