# Cardinal (admin Discord AI bot)

_Scope: Admin-only bot in com.vrca.discordbot: every version v1-v10, memory stores, learner, prompts, admin Bot tab, Cardinal Lab. Measurements live in docs/cardinal-audit.md._

- **Discord AI bot (admin build only, `com.vrca.discordbot`) — v1 shipped**: a self-hosted Discord bot that answers with Cloudflare **Workers AI**, running natively on the admin phone (NOT a WebView, NOT discord.js — the raw gateway protocol over an OkHttp WebSocket, mirroring `VrchatPipelineService`'s foreground + reconnect skeleton). Distinct from `DiscordRpcService` (that's the user's own RPC via a WebView-hosted gateway); this is a real BOT with its own bot token. **`DiscordBotStore`** (EncryptedSharedPreferences `vrca_discord_bot`, same MasterKey/AES-256-GCM scheme as `BotVrchatSession`) holds the secrets ENTERED AT RUNTIME in the admin tab — bot token + Cloudflare account id + Workers AI token + optional AI Gateway id + model + system prompt + ambient% + cooldown + an `enabled` flag; nothing baked in the APK, nothing synced to Firestore, rotatable without a rebuild. **`DiscordBotService`** (foreground, `foregroundServiceType=dataSync`, `stopWithTask=false`, its OWN notif channel `vrca_discord_bot` + NOTIF_ID **1010** so it doesn't collide with the shared 1001) speaks the gateway:
  HELLO(op10)→heartbeat loop (op1, zombie-detects a missing ACK)→IDENTIFY(op2, intents = GUILDS|GUILD_MESSAGES|DIRECT_MESSAGES|MESSAGE_CONTENT = 37377), captures READY (bot id/name, `session_id`, `resume_gateway_url`), RESUMEs(op6) on reconnect via the resume url, handles op7 Reconnect / op9 Invalid-Session (resumable flag) / op11 ACK, and reconnects with exponential backoff (dedup guard like the pipeline's `reconnectJob?.isActive`). **Requires the MESSAGE CONTENT privileged intent** (toggled in the Discord dev portal) for ambient replies. **Trigger gate** on MESSAGE_CREATE (ignores bots/self): an @mention OR a reply to the bot ALWAYS answers; otherwise **ambient** "jump into the convo" fires only when there's readable text AND a `Random(100) < ambientPercent` roll passes AND the channel is off its per-channel cooldown (`ambientCooldownSec`) — the operator-tunable knobs. On a respond it fires the typing indicator, calls `DiscordBotAi.reply` (Workers AI).
  **Short-term memory (v1.1)**: on each reply it reads the last `historyLimit` channel messages via `DiscordRest.fetchRecentMessages` (`GET /channels/{id}/messages`, chronological, the bot's own past messages mapped to role=assistant) and feeds them as chat history — free, stateless, per-channel, survives OS kills (Discord is the store); `historyLimit` (Bot tab, default 8, 0=off, capped 25). No per-user profiles yet. **v1.2 (human flow)**: replies now read like a person, not an assistant — a hardcoded `BEHAVIOR` layer (`DiscordBotAi`) sits on TOP of the admin persona enforcing FORM only (1-2 short lines, in-character, never reveal it's an AI, never lecture/moralise/'break character', deflect-don't-explain); **debounce** (`DEBOUNCE_MS`=1.5s, per-channel `pendingReplyByChannel`) coalesces a burst into ONE reply to the latest message; **reply-chain** context (the `referenced_message` is threaded into history even when older than the fetch window); a cheap **8B ambient triage** (`shouldChimeIn`, `@cf/meta/llama-3.1-8b-instruct`, defaults to stay-quiet on error) gates unaddressed replies before spending the 70B;
  **trivial addressed messages** ('lol'/emoji, `isTrivial`) get an emoji **reaction** (`DiscordRest.addReaction`) instead of a generated reply; **inline @mentions** in message text are resolved to names (`DiscordRest.resolveMentions`, from each message's `mentions` array, zero extra calls); a length-scaled **typing beat** before send; and `max_tokens` trimmed 512→256, and posts via `DiscordRest` (reply-threaded for addressed messages, plain for ambient; `allowed_mentions.parse=[]`+`replied_user=false` so the model's output can never @-ping). **`DiscordBotAi`** routes through **AI Gateway** (`gateway.ai.cloudflare.com/v1/{acct}/{gw}/workers-ai/{model}`) when a gateway id is set (adds observability/retries/fallback — NOT response caching, which is ~useless for unique chat turns), else the direct Workers-AI endpoint (`api.cloudflare.com/client/v4/accounts/{acct}/ai/run/{model}`); the `@cf/...` model id goes in the path literally; default model `@cf/meta/llama-3.3-70b-instruct-fp8-fast`.
  **`DiscordBotState`** is a process-lifetime status singleton (IDLE/CONNECTING/CONNECTED/RECONNECTING/FAILED + a rolling activity log) the admin **Discord Bot tab** (`DiscordBotTab.kt`, tab index 8) observes — the tab has the config fields (token/CF fields as password), Start/Stop, a live status pill + log, and a setup checklist. **Lifecycle**: gated `BuildConfig.IS_ADMIN_BUILD` (the service refuses to start otherwise); Start persists `enabled=true`+`startService`, Stop persists `enabled=false`+stops; `AdminScreen` auto-starts it on app open when `enabled`; `START_STICKY` + the shared swipe/OEM-kill guards (`AppShutdown.isSwipedAway`/`isManualKillFresh`, and it's added to `AppShutdown.stopOtherServices`) mean an OS kill revives it but a deliberate swipe stays dead. **Permanent v2 shipped (on-device, cheapest+quickest — NOT a Cloudflare Worker/DO)**: the bot ("Cardinal") was reworked into a self-developing agent, all in `com.vrca.discordbot`. **`DiscordBotLimits`** = one bumpable place for every ceiling (daily neuron budget + degradation ladder, context caps, per-user/per-channel concurrency, cooldowns, reflection cadences).
  **Self-grown personality, NO admin persona** (`PersonalityStore` rewrite): the ONLY fixed scaffolding is a 2-sentence `ANCHOR`; everything else emerges on three timescales — learned `style` lines (how he talks), weighted `traits` (reinforce/decay, admin can PIN to protect from decay or TEACH at max strength), a slow `mood`, and a few `episodes` (memorable moments). Rendered into the reply prompt as a compact digest. The admin can no longer type a system prompt (`DiscordBotStore.systemPrompt` removed). **Per-user memory** (`UserMemoryStore`, keyed `u_<discordId>`): tiny cards (relationship / a few facts / running bits / sentiment / how-to-treat), and a reply loads ONLY the active participants' cards, so a 40-person server costs the same as a 3-person one. Admin can view/search/edit/pin/teach/delete (memory is moderatable; personality is not). **Cheap routing** (`DiscordBotAi` + `DiscordBotService`): a FREE heuristic scores every message → idle chatter costs 0 model calls, a single-person addressed message goes straight to the 70B reply, and only an ambiguous/ambient moment pays one cheap 8B **director** (reply/react/ignore + rolling thread summary).
  **The 70B reply carries a trailing `%%MEM%%` JSON tail** so ONE call does the reply AND the memory update (no separate memory call). **Fluid concurrency (the "switches to B mid-reply" fix): per-USER debounce buckets** (`pendingByUser`, keyed `channel:user`) so B messaging never cancels A's pending reply, and a **per-channel reply `Mutex`** sequences them (finish-the-thought). **Reaction-learning**: the gateway now subscribes `GUILD_MESSAGE_REACTIONS` (INTENTS=38401) and a reaction to one of Cardinal's own posts (tracked in `recentBotMsgIds`) nudges the reactor's card sentiment. **Budget ladder** (`DiscordBotState.Rung`): FULL → TRIM (trimmed context) → CHEAP (8B replies) → REACT_ONLY → SILENT as the daily neuron estimate fills, so it degrades instead of blowing the free tier. **Shadow mode** (compute, don't send) + **per-channel mute** in `DiscordBotStore`. **`DiscordRest.send`** now returns the created message id (for reaction-learning). **Reflection** evolves traits/style/mood + optional episode every ~20 min;
  **there is NO content restriction on traits or memory** (per the repo owner: a joke trait like "French hater" is a joke, and the old learner-prompt boundary line was removed in Round 3). **Admin Bot tab revamped into sub-tabs** (`DiscordBotTab.kt`): Dashboard (status/counts/mood + Start/Stop + activity) · Personality (view + pin/teach/reset) · Users (memory cards, moderatable) · Traces (why it replied/ignored, from a `DiscordBotState` ring buffer) · Cost (neurons + budget rung) · Controls (shadow / ambient % / cooldown / context / mute) · Config (secrets). **Deferred**: a Cloudflare Durable-Object host (would remove phone-kill fragility but needs the paid plan), image/vision input, and Vectorize semantic recall.

  **adaptive chattiness** (`effectiveAmbient` scales the ambient % by 60s channel activity). **Full emoji** (`EmojiConvert.kt`): the gateway now subscribes **GUILD_EMOJIS (INTENTS=38409)** and captures each guild's custom emojis from GUILD_CREATE; `:name:` in a reply is converted to Discord's real `<:name:id>`/`<a:...>` (custom) or a unicode char (a ~120-entry standard shortcode table) on send, and reactions map via `reactionToken` — the bot can use server emojis + full unicode in messages AND reactions. **Speed/cheap**: instant typing fired before the model call, snappier human delay (`REPLY_DELAY_MIN/MAX_MS`), anti-repetition (its last `ANTI_REPEAT_REPLIES` replies fed back so it doesn't repeat itself), **merged same-author transcript turns** (`mergeTurns`), react-over-reply for trivial, adaptive reply length (`SHORT_REPLY_MAX_TOKENS`). **Context ordering** (deliberate, labelled, no redundancy): identity anchor → self digest → server culture/revived topics (only when retrieved) → people here (compact per-active-user, retrieval-limited) → conversation summary → language/emoji/anti-repeat hints → reply+tail spec → transcript last (chronological, target last, same-author merged).
  **NO model fallback** (per the user — messages never miss). No content restrictions on traits or memory (owner decision). Admin Bot tab Config gained the Analytics token field; Users cards show preferred name + language(s); Cost card reads real-or-estimate. Compiles clean on public + admin.
