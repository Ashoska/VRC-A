# Voice-to-text dictation (headset, offline)

Hands-free dictation into the Manual Send field — built first for **mute players to talk without speaking aloud in-game**. **Headset-only**: the engine is a `headsetAppImplementation` dependency, so public/admin ship stubs (`SUPPORTED = false`) and the UI hides itself. Fully on-device: no audio leaves the headset, no API cost.

## How it works
- **Engine: sherpa-onnx** (`com.vrca.speech.SpeechToText`, headset flavor). One native engine (`libsherpa-onnx-jni.so` + `libonnxruntime.so`) runs every model family we use, so adding a language = adding a downloadable pack, not code.
- **Phrase-based decoding** (live words, below, re-read the unfinished phrase). Capture thread: `AudioRecord` (16 kHz mono, `VOICE_RECOGNITION`) → AGC → **Silero VAD** (`threshold` from the mic sensitivity, 0.5 by default; `minSilenceDuration` 0.4 s ends a phrase, `maxSpeechDuration` 15 s splits monologues). Each finished phrase goes on a queue with its start sample; a separate decode thread **normalises its loudness to ~-24 dBFS** (quiet audio badly hurt some engines in testing) and recognises it. The capture thread never blocks, so no speech is lost while a phrase decodes. On Stop the VAD is flushed and the decoder drains the queue before exiting (a `captureDone` flag — exiting on `running=false` alone lost the last phrase).
- **Breathing / noise (user-reported: "Hearing you" fired on every breath, flickered, lagged, and lingered after speech).** `Voicing` (shared, pure) checks each 32 ms window for a pitch: 250 Hz high-pass, then a normalised-autocorrelation PEAK at 70–400 Hz ≥ 0.6. Tested (throwaway) on 250 real clips in 10 languages incl. tonal + AMI casual talk: 0 rejected; synthetic breath, mic rumble, fan, clicks: ≤ 2 voiced windows. Used three ways: (1) a short VAD segment with too few voiced windows is dropped WITHOUT decoding (how short / how few is the mic sensitivity's call, below; noise used to cost a 1 GB-model decode and delay the next real phrase); (2) `onSpeechActive` (UI "Hearing you…", VRChat typing dots) goes on after 3 voiced windows (`MIN_VOICED_WINDOWS`, every sensitivity) and off when the VAD phrase ends OR 12 windows (~0.4 s) after the voice stops; (3) the AGC learns the level from VOICED windows only and holds still between (gain 1× up to the sensitivity's cap, 6× on Normal) — the old AGC tracked any sound, climbed toward 8× in silence and amplified breathing into "speech". Raw pre-emphasis wasn't enough (rumble still looked periodic); the high-pass + interior-peak rule is what separates them.
- **Field integration** (`VrcaViewModel.startDictation`/`queueSpeechPhrase`/`appendSpeechPhrase`): dictation forces Live + Scroll on; phrases are **appended to the CURRENT field text** via `onMessageTextChange` (so scroll windowing applies). It deliberately does not keep its own transcript — the Live hold expiry clears the field, and a remembered transcript would resurrect old text with the next phrase.
- **Mic sensitivity (`MicSensitivity`, picker row, global, live)** — user tested: breath filter worked but soft words got missed (VAD 0.6 + every unvoiced phrase dropped + 6x boost cap was too strict). Levels: **Soft voice** (VAD 0.45; drop only unvoiced blips < 0.5 s with < 2 voiced windows; boost up to 10x), **Normal** (default; VAD 0.5; drop unvoiced blips < 0.8 s; boost 6x = the breath-free tested value), **Noisy room** (the old strict settings: VAD 0.6, every unvoiced phrase dropped). Boost never changes accuracy (every phrase is evened to -24 dBFS before decoding), only what gets picked up. Switching mid-dictation flushes + rebuilds only the voice detector (0.6 MB); the speech model stays loaded. Saved in `vrca_speech` prefs `sensitivity`. Every phrase also gets **0.5 s before / 0.2 s after** the VAD's cut from the ring buffer (`PRE_ROLL`/`POST_ROLL`; never before the previous phrase's VAD end): the VAD reacts late and ends early, clipping soft first/last syllables (0.25 s still lost first words like "finally"/"forever", user-reported); pauses are still measured on the VAD's own bounds (`Segment.start`/`end`).
- **Joining phrases (`PhraseJoin`)**: each phrase is decoded alone, so models end every one with a full stop + capital — wrong after a mere breath ("I think we should. Go…", user-reported). The closing "." is stripped (? ! … kept); a phrase whose `pauseBeforeSec` (silence since the previous phrase that produced text, from VAD sample positions) is < `SENTENCE_PAUSE_SEC` (1.5 s) continues the sentence (first word lower-cased, except I/I'm…, acronyms, and German, where nouns are capitalised); ≥ 1.5 s appends "." to the previous text (or the last queued piece) and keeps the capital.
- **Pacing (`CaptionPacer` in `ChatboxScroll.kt`)**: roll-up captions. Text that scrolls nothing off goes in at once; otherwise one line at a time (`ChatboxScroll.nextPiece` fills the bottom line then one full line), at most one per `SPEECH_SCROLL_GAP_MS` (1.5 s) and only once the line leaving has been readable for `SPEECH_MIN_LINE_MS` (6 s). Before: a phrase longer than the 4-line window landed whole and its start scrolled off unseen (simulated: "Someone said we should go to the Black Cat," never showed). Normal speech (~2 s/line) never waits. Stop lets the queue finish; Clear drops it.
- **Live words (every model, user request "make the phrase models live")**: phrase models can't decode word by word, so while you talk the capture thread keeps a 20 s ring buffer of the gained audio and, once the VAD phrase has ≥ 3 voiced windows and ≥ 0.5 s, hands the decode thread a copy of the unfinished phrase (starting 0.3 s before the VAD trigger) to re-read; `Listener.onPartial(text, pauseBeforeSec)` shows "the sentence so far". Finished phrases always decode first (decode thread polls them 50 ms, re-reads only when none waits; a re-read whose phrase got queued meanwhile is dropped via `finalsQueued`). Pace = 2.5× the measured re-read time, clamped 0.8–5 s (`LIVE_MIN_MS`/`LIVE_MAX_MS`), so it adapts per model/device and stays ≤ ~40% of the decode threads next to VRChat; no re-reads past 12 s (`LIVE_MAX_SEC`).
  **Lock-in (`LiveAgreement`, shared/pure)**: words two re-reads in a row agree on are locked and the next re-read starts 0.15 s before the first open word (`LiveState.cutSec`), so a re-read covers ~2–3 s however long the phrase (prototyped on the bench: Parakeet 2.2 s vs 5.0 s whole-sentence, GigaAM 2.6 vs 5.6, SenseVoice 2.7 vs 7.0; live text within ~2–6% of the final). Needs token timestamps (`PhraseDecoder.hasTimes`; Canary + Whisper have none → whole-sentence re-reads). Word grouping: "▁"-prefixed tokens or a bare "▁" token (GigaAM) start words; CJK characters are words.
  **No lag for VRChat**: the recognizer is created at `THREAD_PRIORITY_BACKGROUND` (ONNX Runtime's worker threads inherit it) and the decode thread runs at it; capture runs at `THREAD_PRIORITY_AUDIO`. **Memory guard**: `start` refuses a pack only when it can't fit in `availMem` ("pick a lighter tier"); the old rule (low-memory line + 300 MB on top) refused packs that fit (user-reported), and under pressure Android reclaims a background app like ours before VRChat. Live words add only ~2 MB (ring buffer). Live re-reads wait for 6 voiced windows (`LIVE_MIN_VOICED`, ~0.2 s of voice) so a cough or hum doesn't flash a made-up word.
  **`SpeechFilter`** (shared, pure) drops what models invent from noise (user-reported: "okay" appearing while silent): a lone filler (okay/yeah/mm/uh/the…) backed by < 8 voiced windows, and a phrase with next to no voice (below the sensitivity's bar, decoded only because it was long) unless it has ≥ 3 words (CJK ≥ 4 characters). **Live / Phrases toggle** (`SpeechPacks.liveEnabled`, chip "Live words"/"Phrases" next to the language chip; not "Live" — Manual Send's typing switch is Instant/Live) applies instantly via `SpeechToText.setLive`. VM: `showSpeechPartial` keeps the field before the phrase (`speechLiveBase`, with its sentence mark decided ONCE at the first partial) and replaces the live tail each time; the final replaces it in place (`finishSpeechPartial`, bypassing the pacer since the words are already up); an empty final (segment was noise: queued with `noise=true`, never decoded) takes the live words back. Field cleared/edited meanwhile → the final is queued normally.
- **Hold + Clear**: dictated text stays `SPEECH_HOLD_MS` (8 s) after the last words, then the chatbox goes back to normal (typed messages keep 20 s; dictation edits set `speechChanging` so `onMessageTextChange` marks `lastChangeBySpeech`). **Clear** calls `SpeechToText.discardPending()` (an epoch: phrases queued/decoding before Clear are dropped, so a sentence finishing right after Clear can't put text back) and re-sends the revert at +0.6 s and +1.3 s: VRChat drops a chatbox message < 0.5 s after the previous one, and a live send may have just gone out, so a single revert was often swallowed (user: "clearing doesn't go back to the normal chatbox").
- **Latency**: each appended piece restarts the live loop so it reaches VRChat at once (not on the next 0.5 s tick; never < 0.5 s after the last send). Once the words stop changing, the same text is only re-sent every 3 s (`MANUAL_REFRESH_MS`, see chatbox.md), not every 0.5 s (user-reported flood while quiet); `minSilenceDuration` 0.4 s. The row shows "last took X s" (model time per sentence, `speechLastDecodeMs`) while listening, to tell model speed from the pause it waits for.
- **Listen trigger (`SpeechPacks.listenParam`/`listenWhenOn`, picker "Listen" row → `ListenTriggerDialog`)**: user idea: start hearing instantly without the model's load time. Pick any on/off avatar param VRChat reports over OSCQuery (`VrcaOscState.boolParams`, live list with "On now/Off now"; MuteSelf, Earmuffs, AFK first, then the avatar's own toggles like an "STT" Action Menu toggle) and listen while it's on or off; default Always. The VM re-checks every 250 ms while dictating (`applySpeechGate` → `SpeechToText.setGate`). Closed = the capture thread flushes the sentence in progress (it was said while listening), then stops feeding the VAD: no Hearing you, dots or text, but the model stays loaded and mic + ring keep running, so reopening is instant; the first word may use ≤ 0.25 s of pre-roll from before the switch (noticed late), never more. A param VRChat doesn't report right now (`freshBool`: not seen for 3 s = not on this avatar / VRChat closed) = listen anyway, and the row says so; paused, the row reads "Paused · Listens while …". Only this trigger pauses: the mic button still stops and frees the memory.
- **Sentence timeout (`SPEECH_SENTENCE_MS` 10 s, user request)**: each dictated piece (a finished phrase, or one line of a rolled-in long one) leaves the chatbox 10 s after it went up, oldest first, while newer words or live words stay; alone, the 8 s hold after the last words clears everything first. VM: `noteSpeechShown` logs each piece's size in `ChatboxScroll.units` (words, or letters for no-space scripts; punctuation never counts, so a later full stop shifts nothing) + time; `expireOldSpeech` (every 0.5 s) rebuilds the field from `ChatboxScroll.keepLastUnits` (and the live base when live words show). Every dictation write goes through `setFieldBySpeech`, so a field cleared/reverted/typed in by anything else stops the timeout. A timeout cut sets `speechExpiredText`: the live loop doesn't extend the hold or show dots for it (it isn't new speech).
- **Voice commands (`VoiceCommands` + `CommandSounds`, shared; engine in `SpeechToText`)**: a command word said ON ITS OWN (the whole phrase) pauses, resumes or clears. Defaults per language (en pause / resume·unpause / clear; es pausa / continuar / borrar; zh 暂停 / 继续 / 清除 …); users replace them per language in the picker's "Voice commands" dialog: "Say it" records the word `LEARN_TIMES` (3) times through the running model and saves what it actually heard ("paws" for "pause" matches then), "Type it" for spellings; warns on short/everyday words or words heard differently each time, and refuses a word another command uses. Prefs `commands`, `cmd_<lang>_<COMMAND>`.
  **False-trigger checks (user: "make this not have false triggers")**: whole phrase = the word (letters/digits only compared, so "Pause."/"un-pause" match, "pause the video" doesn't); ≥ 1 s of quiet before it (`QUIET_BEFORE_SEC`, from the last words that went in); clearly voiced (≥ 6 voiced windows) and ≥ half the wearer's usual voice level (median of the last 20 dictated phrases' voiced RMS before gain, `Segment.level` = `Voicing.voicedStats` ÷ AGC gain): other people and VRChat's own sound from the Quest speakers reach the mic quieter; then it waits `CONFIRM_MS` (0.5 s): if you start talking again (`talkStartedAt`), it was conversation and goes in as text. Commands that change nothing do nothing (pause while paused; clear with nothing to clear = no sound either). Live words that could still be a command (`couldBe`: a prefix of a command word) are held back, so a command never flashes in the chatbox.
  **Paused by voice**: the engine keeps hearing (to catch the resume word) but nothing goes in: no partials, finals dropped, no Hearing you / typing dots; the row says "Paused by voice · Say "resume" to carry on". The trigger pause (Listen trigger) is different: it stops hearing. Each fired command plays a chime (falling = paused, rising = resumed, double blip = cleared; generated tones, sonification usage) and the mic is ignored for 0.6 s (`CommandSounds.MIC_IGNORE_MS`) so the chime is never heard as speech. During "Say it" the engine's commands are off and finals are recorded instead of typed.
- **Typing dots**: `onSpeechActive` sets `/chatbox/typing` while you talk (VrcaOsc's setter still suppresses it with the invisible border); the live loop doesn't drop the dots while `speechHearing`.
- **Background (`DictationService`, headset flavor, `foregroundServiceType="microphone"` + `FOREGROUND_SERVICE_MICROPHONE`)**: Android silences a backgrounded app's mic unless a microphone FGS runs, started while the app is on screen — dictation stopped after ~1 phrase once the user switched to VRChat. `SpeechToText.start` (the mic tap, on screen) starts it; the capture thread's `finally` stops it; `onTaskRemoved` stops dictation. Start failures are caught (dictation then works only on screen). A game in front that holds the mic itself may still win under Android's input-sharing rules — confirm on device. **Quest shows no app notifications**, so the FGS notification (Android requires one; it has a Stop action for phones) is invisible there.
- **Keeps running off-screen**: collapsing Manual Send or switching tabs no longer stops dictation (the row's old `onDispose` stop cut people off). Stop = the row's mic button, or the **red mic in the top bar** (`VrcaScreen` actions, shown only while `speechListening`, every tab), plus "Voice to text is on" as the collapsed card's summary. `Listener.onStopped` (from the capture thread's `finally`) resets the VM for every way it can end (button, notification, error, task removed).
- Listener: `onPartial(text, pauseBeforeSec)`, `onFinal(text, pauseBeforeSec, decodeMs)`, `onError`, `onSpeechActive`, `onLoading` (model load, a few seconds), `onStopped`. The recognizer (~1 GB for Parakeet) is loaded on mic tap and released on Stop — zero RAM when idle.

## Language packs (`SpeechCatalog`, `SpeechPacks` — shared code)
- `SpeechCatalog.languages` maps each language → its **tiers** biggest-first (`Tier(packId, label, errorPct)`: **Large / Medium / Small** — named by size, the real trade-off, since quality shows as the accuracy % beside it; renamed from Best/Balanced/Light because "Best · 83% OK" read as a contradiction — or "Standard" when a language has only one) so users can trade accuracy for storage + RAM; quality labels (Excellent/Great/Good/OK/Experimental) are derived from the measured accuracy (picker bullet). The chosen tier is saved per language (`vrca_speech` prefs `tier_<code>`). `packs` lists files, each **pinned to an exact upstream revision** (Hugging Face `resolve/<commit>/…`) with exact **size + SHA-256**. The Silero VAD (0.6 MB) is a shared pack downloaded with the first language.
- `SpeechPacks.downloadLanguage`: one download at a time, checks free space first (+50 MB margin), **resumes** from `<file>.part` via HTTP Range (redirects followed by hand so Range survives the hop to the CDN; a 200 reply to a ranged request restarts the file), verifies SHA-256, and only then writes the `.ok` marker. Installed = `.ok` exists AND every file has its exact size. Location: `filesDir/stt/<packId>/` (not cacheDir — the OS may wipe cache). `deletePack` removes a pack and the VAD once no language pack is left. `cleanupLegacy` deletes the old Vosk model dirs (`filesDir/vosk-model*`) from the first build AND any `stt/<id>` dir the catalog no longer lists (e.g. GigaAM v2 after the switch to v3), since Settings only shows catalog packs.
- Selected language: `vrca_speech` prefs (`lang`); default = device language if offered, else English. Saved with `commit()` (not `apply()`: closing the app right after picking could lose it), loaded in the VM's `init` (not only once the row composes). Picking another tier WHILE a pack downloads cancels that download and fetches the new pick (`speechDownloadAfterCancel`); it used to be silently ignored, so the old choice "came back" after a restart (user-reported "doesn't save"). While not installed, the row's hint names the selected language/tier.
- Engine kinds (`SpeechCatalog.Kind`): `NEMO_TRANSDUCER` (Parakeet), `NEMO_CTC` (GigaAM v3, `OfflineNemoEncDecCtcModelConfig`, 80-dim features as in the benchmark), `CANARY` (language passed as `srcLang`/`tgtLang`, 128-dim features), `ONLINE_TRANSDUCER` (Kroko streaming zipformer, fed one phrase at a time + 0.8 s silence tail), `TRANSDUCER` (offline zipformer, `modelType "transducer"`: ReazonSpeech, Vietnamese), `SENSE_VOICE` (language = our code zh/yue/ko, ITN on), `OMNILINGUAL_CTC`, `DOLPHIN_CTC`, `ONLINE_CTC` (small streaming Chinese), `WHISPER` (language explicit, files found by `contains` since they're named base-*; no timestamps). Streaming kinds share `online()`. Each sits behind `PhraseDecoder` in `SpeechToText`, configured exactly like the bench's sherpa call; file names are resolved from the catalog by prefix. `Pack.slow` → "Slower" in the picker (Omnilingual-1B, ~1× real time per core on desktop; Whisper base, which always encodes a 30 s window).
- **Why Spanish scores higher than English** (user asked): each language has its OWN FLEURS sentences (English's are dense with names/numbers), English spelling is irregular so every model does worse on it (NVIDIA's own Parakeet v3 FLEURS numbers: ~3.5% Spanish vs ~4.9% English), and 20 clips = ±2–3 pts. So % compares tiers WITHIN a language; the picker footer says so. Parakeet EN is still the best English model that runs on a Quest CPU (won real talk, chatter and clean; only Granite 1B beat it, slower than real time + ~2 GB).
- **Accuracy shown per tier** (user: "spanish has 3 greats" was confusing): `Tier(packId, label, errorPct)` holds the FLEURS % wrong (same yardstick for every language; English re-measured on FLEURS too: Parakeet 7.8, Canary 16.7, Kroko 19.8); the picker's quality badge shows "label · `accuracy`%" and the label is DERIVED from the rounded accuracy (see the picker bullet), never hand-set. The footer says quality is measured on test recordings (casual talk does a bit worse) and to compare sizes within a language.
- **Tier rule** (user: most languages get 3 tiers, the smallest = cheapest in space + RAM and the 3rd best): Large = most accurate; each lower tier must be smaller in download AND RAM (or, for Dolphin base vs SenseVoice/ReazonSpeech, a much smaller download at about the same RAM) and ≤ ~25% wrong. Round 3 (`tools/speech-bench/results-2026-10-round3.txt`) found the smaller tiers in the table below. Whisper tiny was unusable (22–100%); Whisper base was too weak except for Portuguese. Still one tier (nothing smaller is decent): Italian, Polish, Ukrainian, Dutch, Bulgarian, Vietnamese (already 77 MB), Turkish (Omnilingual-300M 29.8).
- **Tiers are different MODELS, not sizes of one model** (SenseVoice/Parakeet/GigaAM come in one size): a language only gets Medium/Small when a separate smaller model is still decent. Dolphin small (250 MB, ~600 MB RAM) is NOT lighter than SenseVoice, so the Small tier for Cantonese/Japanese/Korean/Thai/Indonesian is Dolphin **base**. Omnilingual-300M is the Small tier only for Hindi/Filipino (Experimental).
- **No-space scripts (zh, yue, ja)**: `PhraseJoin.joiner` joins phrases without a space and closes sentences with "。"; `ChatboxScroll` counts CJK/full-width characters as 2 units (VRChat draws them ~2 Latin letters wide), breaks at 。！？，、 and feeds no-space text character by character in line-at-a-time mode.

The hint text is always exactly 2 lines (`minLines`/`maxLines`) so Listening ↔ Hearing you never changes the card height (it jumped the layout as it toggled). ## Build / packaging notes
- Dependency: official AAR `com.github.k2-fsa.sherpa-onnx:sherpa-onnx:v1.13.8@aar` from **JitPack**, declared in `settings.gradle` as `exclusiveContent` filtered to that group (JitPack can't serve anything else). The top-level `com.github.k2-fsa:sherpa-onnx` JitPack artifact also drags desktop/JVM natives — do not use it.
- Headset flavor: `ndk { abiFilters "arm64-v8a" }` (every Quest is arm64; strips the other ABIs' engine copies). `packaging.jniLibs` excludes `libsherpa-onnx-c-api.so` / `-cxx-api.so` (JNI lib needs only `libonnxruntime.so`, verified with readelf; ~2 MB saved). Headset manifest keeps `extractNativeLibs="true"` so the ~25 MB of native libs are stored compressed in the APK.
- ProGuard: `-keep class com.k2fsa.sherpa.onnx.** { *; }` — the JNI layer reads config fields **by name**; R8 renaming them breaks release builds.
- Kotlin API used: `OfflineRecognizer(config = OfflineRecognizerConfig(featConfig, modelConfig = OfflineModelConfig(transducer = OfflineTransducerModelConfig(encoder, decoder, joiner), tokens, numThreads, modelType = "nemo_transducer"), decodingMethod))`, `createStream/acceptWaveform/decode/getResult/release`; `Vad(config = VadModelConfig(SileroVadModelConfig(...)))` with `acceptWaveform/empty/front/pop/isSpeechDetected/flush`.
- Planned size trim (later): a reduced-operator ONNX Runtime build (~3–5 MB instead of ~7.6 MB compressed).

## Known limits / next steps
- **Background**: built (`DictationService`) and confirmed on a Quest 3: keeps listening with VRChat in front, breathing doesn't trigger it, it didn't seem to cost frames, Parakeet EN ~0.3 s per sentence (user test, Oct 2026). Frame/RAM cost isn't profiled; the memory guard refuses packs that would squeeze VRChat.
- **Whispering** has no pitch, so the voicing filter sees it as breath: no "Hearing you"/typing dots and no live words for it, and on Noisy room it's dropped. On Normal/Soft a whispered phrase the voice detector catches still reaches the model if it's longer than the blip limit (0.8 s / 0.5 s). If mute players whisper, a dedicated level may be needed (open question).
- Later, only if asked: Canary-1B for European languages (~1.9 GB RAM), a self-hosted single-file Thai zipformer, a reduced-operator ONNX Runtime build (smaller APK).

## Engine shoot-out (Oct 2026) — why these models
Desktop CPU, same audio for every engine; % = words wrong (characters for zh/yue/ja/ko/th).
- **English, real conversation (AMI headset mics) / with 3 background talkers / clean read speech:** Vosk small 38.4 / 47.3 / 9.6 · Vosk 128 MB lgraph 29.7 / 40.2 / 6.8 (and only ~1× real time — too slow) · Vosk 1.8 GB 26.2 / 33.9 / 5.2 (**5 GB RAM**) · Kroko 22.5 / 7.7 / 5.4 · Moonshine Medium (live) 20.0 / 13.2 / 2.2 · Whisper small 18.6 / 7.6 / 3.3 · **Parakeet EN 14.2 / 4.0 / 1.6** · Granite 1B 13.0 / 2.4 (same subset: Parakeet 15.7 / 3.4) but slower than real time on CPU + 2 GB RAM.
- Vosk's published numbers are real (measured 9.6 vs claimed 9.85 on audiobooks) but it collapses on casual speech and background chatter — the old design, not its size, is the problem.
- **25 European languages (FLEURS, 20 sentences each, ±2–3 pts):** Canary-1B (language is specified → cannot confuse languages) won 21/25. Parakeet-25 is fine only for Spanish (2.2), Portuguese (4.5), Russian (10.6) (later checks: also German 6.0 and Italian/Bulgarian/Polish/Ukrainian/Dutch, where it never answered in another language, so it serves those now); it auto-detects language and wrote the wrong language for 40% of Slovenian and 10% of Croatian sentences, and even with confusion removed stayed ~2× worse than Canary on small languages. Its int8 build underperforms its published scores on small languages. Whisper small is worse than both.
- **Asian:** Japanese → ReazonSpeech zipformer 5.3 · Cantonese 5.5 / Chinese 8.0 → **SenseVoice 2024-07-17** (the **2025-09-09 build is broken** for ja/ko/en: 77–79% garbage) · Korean → Whisper small 4.0 (Korean zipformer 39.3) · Thai → Thai zipformer 7.9 · Vietnamese → Vietnamese zipformer 10.8.
- **Other:** Omnilingual-1B (Meta, 1,600 languages) won all: Indonesian 9.7, Hindi 11.4, Turkish 14.9, Filipino 16.5, Arabic 19.0, Malay 19.8, Persian 19.8. Hebrew 40.1 everywhere → not offered. Omnilingual-300M is clearly weaker. Dolphin has no Turkish/Hebrew.
- Moonshine non-English models print a non-commercial licence warning in their library despite the README saying MIT — verify before shipping any.
- **Round 2:** Russian → **GigaAM v3** (e2e CTC, punctuated) **6.6**, the best of all (Parakeet-25 10.6, GigaAM v2 11.2, Whisper turbo 9.7, Qwen3-ASR 24.1) and also fast (0.14× real time) + light (~450 MB RAM). Tested via onnx-asr; shipped since through k2-fsa's sherpa export (6.2 there). Chinese/Cantonese/Japanese/Thai/Vietnamese: round-1 picks hold (Paraformer zh 11.8; Qwen3-ASR 0.6B only wins Korean, 2.9 vs Whisper small 4.0, but needs ~2.4 GB RAM).
- Whisper large-v3-turbo is far more accurate for Turkish 7.0 / Malay 9.8 / Indonesian 6.2 (Omnilingual-1B 14.9 / 19.8 / 9.7), and ivrit.ai's Hebrew turbo makes Hebrew usable (19.7 vs 40+), but it runs ~2× SLOWER than real time on one desktop core (Whisper always encodes a 30 s window, even for a 3 s phrase) with ~1.8 GB RAM, so it's too slow for live chat on a Quest CPU. Parked (maybe later on the GPU).
