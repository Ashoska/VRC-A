# Public UI kit, dialogs, timezones

_Scope: Gremlin design system (`GremlinTheme`, `GremlinColors`, M3 1.4 look-keepers, `GremlinSlider`, toolchain versions), PublicUiKit components, VrcaDialogs (card dialogs), PanelScale (headset fixed panel, PanelDialog), TimeZones helpers._

### Building UI: the checklist (every new screen, redesign or UI fix)
One list of what all UI must follow; the details are in the sections below and in the docs named.
- **Look:** colours only from `GremlinColors` / `MaterialTheme.colorScheme` (never `Color(0x…)` outside `ui/theme/`). Depth = flat layers (`Backdrop` → `Panel` → `Card` → `Raised`) + `Edge` lines, never gradients. Surfaces, cards and menus take their tint from the theme's surface-container roles (don't hand-pick greys).
- **Components:** buttons are `GremlinButton` (`ui/common/GremlinButton.kt`), never Material `Button`/`OutlinedButton`/`TextButton`. sliders are `GremlinSlider`, never Material `Slider`. Dialogs are `PanelDialog` / the `VrcaDialogs` card dialogs, never a plain `Dialog`/`AlertDialog`. Cards, toggles and rows come from `PublicUiKit` (`CompactSectionCard`, `TogglePill`, …). Bottom-nav items use the shared colours (selected label `onSurface`).
- **Layout:** design for the headset's fixed 1024x640dp panel AND the phone (411x891dp); the headset scales one panel, it never reflows (headset.md). Public UI follows docs/ui-revamp.md (collapsed = status, expanded = control).
- **Copy:** no backend names ("Firebase"/"Firestore") in public UI, no em dashes in onboarding/login copy, admin UI has labels/values/controls only (no helper paragraphs).
- **Everything shown is watched state.** Show only `mutableStateOf`/snapshot collections, `collectAsState()` of a flow, or `derivedStateOf` of those. Never a plain field, prefs/encrypted-store read, `StateFlow.value` or clock read in a composable body. Signed-in VRChat state and name: `VrchatAuthManager.session` (never `isLoggedIn`/`getStored*` in a body).
- **Never mutate what you pass down.** Strong skipping is on: a child skips when every argument is the SAME instance as last time, so changing a list/object in place (`list.add`, `obj.x = …`) and passing it again shows the old content. Make a new value (`list + item`, `copy(...)`) or hold it in `mutableStateListOf`/`mutableStateOf`.
- **Draw/layer/layout blocks read their state up front.** A `graphicsLayer {}`/`drawBehind {}`/`offset {}`/`layout {}` block re-runs only when STATE it read changes; under strong skipping nothing else re-applies it (before, any rebuild recreated the lambda). So never read a plain holder (coordinates array, cached field) there, and never return early before reading the state that should wake it: put changing values (positions, sizes) in `mutableStateOf`, written only when they change. Found the hard way: the boot logo stopped starting centred (its layer block read no state on the first frame). Check animations frame by frame in the lab (`record`), not only with `perf`.
- **Performance:** animations read in draw/layout lambdas only (`Motion.kt` helpers); nothing slow while composing; narrow inputs; stable `key`s in lazy lists; big pages built over frames (`StagedBuild`) or behind the boot screen. Full rules: "Performance rules" below.
- **Check before asking for a build:** compile public, admin and headset; UI Lab shots on headset + phone (layout, both look identical to the rest of the app); UI Lab `perf` on the screens touched (no rebuild streaks, no unexpected heavy frames); change each shown source in the lab (`set`/`preset`) and see it update.

### Buttons (`GremlinButton`, revamp 2, user pick 2026-10-23)
- The look ("B" of the button sheet, chosen over layered, tinted, cat-ear, underline, notched, icon-block, speech-bubble, boot-line, bracket, echo, doodle and subtler variants, which were removed): a dark `Card` face with a 1.5dp outline and label in the button's colour, 14dp corners; pressing fills it with its colour (22%) and thickens the outline. Kinds: `Primary` (accent: the main action), `Secondary` (`Edge` outline, `Text` label: side actions), `Danger` (red: stop / destructive). No text-only kind (user, 2026-10-25: the old `Quiet` text buttons looked like labels; every action, Cancel and Back included, is a real outlined button now). Sizes: Large 52dp (Start sending, Retry, crash screen), Medium 44dp (default), Small 34dp (inline). Disabled = 40% alpha.
- Two forms: text (`GremlinButton("Label", onClick, icon =, trailingIcon =, leading =)`) and free content (`GremlinButton(onClick) { … }`, `GremlinSecondaryButton`, `GremlinSmallButton` (Secondary at Small, for inline actions: Add row, Edit, Reset, Model credits): the stock Material shape, so the old 94 buttons swapped over by name, and the admin app's 81 Material `Button`/`OutlinedButton`/`TextButton`s followed on 2026-10-25 (red-coloured ones became `Danger`, tight-padded ones Small); no Material buttons are left in the app; text/icons inside take the button's colour via `LocalContentColor`/`LocalTextStyle` unless they set their own, so don't give them `onPrimary`/`onError` colours).
- `loading = true`: Boot Cat thinking appears in front of the label (in place of the icon), taps are ignored, and the caller changes the label (e.g. "Downloading", login "Sign In" while it checks). Replaced the in-button spinners (update dialog, login, 2FA). `leading` takes custom content (the boot Retry countdown: `BootCatCountdown`, the cat whose outline drains with the seconds left).
- Downloads: `bootIcon = BootIcons.Updates` (our eared-parcel download symbol, not Material's) and `downloading = true` + `downloadProgress` (0..1, null = size unknown) swap the icon for the download Boot Cat (`BootCatDownload` in `BootCat.kt`): the head outline fills clockwise from the top middle with the real progress (spring-smoothed), a lighter glint runs along the filled part every 1.4 s and the v eyes (user preferred them to full arrows) run a 4.8 s loop of three 1.6 s beats: two download beats (rest, glide down and fade out, drop back in from above and settle, all eased) and a second state like the thinking cat's "hmm" (the v's squint flat, hold, open), so a slow download never looks stuck; unknown size = the thinking cat's running light. Finish: `downloaded = true` (`BootCatDownload(done = true)`) lands him into the Done face with the boot rows' blink-and-pop (`BootCat(startFrom = Mark.Working)`); the label is not changed (the cat says it). Used by the update popup (VrcaApp polls DownloadManager bytes every 500 ms on IO while `downloadId` runs; label "Downloading N%"; on success `downloadLanded` shows the Done landing for `LANDED_HOLD_MS` 1.1 s, then the installer opens) (the crash screen's Start VRC-A uses the same eared tile, `BootIcons.Start`). Lab: `show download`, `show downloadcat` (one big cat, 0% for 1.2 s then 0->100% over 10.8 s, then lands into Done).
- Press and colour animations are read in `drawBehind`/`graphicsLayer` only (repaint, no rebuild). Lab: `show buttons` (every kind x Normal/Pressed/Disabled/Loading, and the sizes; `pressedPreview` forces the pressed look there).

### Gremlin design system (`ui/theme/`)
- **Gremlin** is VRC-A's own design system (user-named, 2026-10-16: "start marking things as our own"; it replaced the SlimeVR-derived `Slime*` palette, values unchanged, lab-verified pixel-identical). `GremlinTheme` (was `VrcaTheme`) / `GremlinOverlayTheme` (was `OverlayTheme`) build the Material scheme (`GremlinDark`/`GremlinLight`) from `GremlinColors` + `GremlinShapes` + `GremlinTypography`.
- **`GremlinColors`** (`Color.kt`) holds every colour: accent (`Accent`, `AccentSoft`), the **layers** back to front `Backdrop` → `Panel` → `Card` → `Raised` plus `Edge` (where layers meet), text (`Text`, `TextMuted`), app tones (`Success`/`Warning`/`Error`), signals (`Positive`, `Caution`, `Negative`, `Alert`, `Inactive`) and named groups: `Status` (VRChat status dots), `Trust` (by displayed rank), `Platform`, `Performance`, `Access` (instance type), `Change` (diff lists), `Highlight` (self/friend), `Medal`, `Quality` (voice packs), `Callout` (rich docs).
- **Rules:** no `Color(0x…)` outside `ui/theme/`; add a named token instead. Depth comes from flat layer steps and `Edge` lines, **never gradients** (user: gradients look bad). The move unified a few duplicate shades: roster trust shields now use the VRChat-tab trust colours, busy red is one shade, the "granted"/onboarding greens are `Positive`, the onboarding amber is `Caution`.
- **Material 3 1.4 look-keepers** (Compose upgrade, BOM 2026.06.01): M3 1.4 draws cards/sheets/menus from the `surfaceContainer*` roles, which our scheme never set (they defaulted to greyer tones). `withGremlinSurfaceContainers()` (`Theme.kt`) fills them the way M3 1.1 tinted surfaces: `primary` at `(4.5*ln(e+1)+2)%` over `surface` (Low e=1, Container e=3, High/Bright e=6; Lowest/Dim = surface, Highest = surfaceVariant). Ripples: `RippleTheme` is gone; the headset provides `LocalRippleConfiguration` with `NoHoverRippleAlpha` (no hover glow from the Quest pointer). Sliders: use `GremlinSlider` (`ui/common/GremlinSlider.kt`, thin 4 dp track + round 20 dp thumb), never a bare Material `Slider` (1.4 restyled it to a thick split track + bar). Bottom nav items pass `selectedTextColor = onSurface` (1.4 changed the selected label to `secondary`). The notification badge is slightly larger in 1.4; kept. Cards: 1.4's `Card`/`ElevatedCard` no longer tint a `surface` container by elevation (`Surface(tonalElevation)` still does), so a card that relied on it names the role instead: `VrcaCardDialog` (What's New + every confirm) = `surfaceContainerHigh` (was 6 dp), the update dialog = `surfaceContainerLow` (was 1 dp). Never give a card `containerColor = surface` + elevation to get a lighter tone; use the container roles.
- **Toolchain** (2026-10, two steps): (1) Gradle 8.14, AGP 8.13, Kotlin 2.4 + Compose compiler plugin, Compose 1.11 / M3 1.4, compileSdk 36. (2) Gradle 9.7, AGP 9.4, Compose 1.12.1 (BOM 2026.09.00), compileSdk 37 (target stays 34), strong skipping ON.
- **AGP 9 notes:** built-in Kotlin (the root `kotlin-android` plugin line only picks the Kotlin version; never apply it in `app/`), `buildFeatures.resValues true` (flavors set `app_name`), `packaging {}` (not `packagingOptions`), no `android.nonFinalResIds=false` (R8's resource shrinking needs non-final ids), `android.r8.strictFullModeForKeepRules=false` in gradle.properties (AGP 9's strict mode drops the no-arg constructor a plain `-keep` used to keep: WorkManager's `WorkDatabase_Impl` and Firebase `ComponentRegistrar`s lost theirs, so the first AGP 9 release died silently before its first frame on the headset; check a release APK's reflective classes with `dexdump` before trusting a new AGP),.
- **AGP 9 release shrinking:** R8 moves renamed classes into the UNNAMED package (AGP 8 kept obfuscated packages), so `Class.getPackage()` returns null: javaosc's `Activator` called `getPackage().getName()` and every OSC send threw an NPE (2026-10-22) -> `-keep class com.illposed.osc.**` in proguard-rules.pro. Scanned the release dex for other `getPackage` callers: Lifecycling and OkHttp AndroidLog null-check, Compose ChangeList is debug text, gRPC InternalLogId only for anonymous classes, VersionedParcel unused. The UI Lab runs the debug build (no R8), so release-only breaks never show there: check the release APK itself, `settings.gradle` lists `google()` before the plugin portal (the portal sends AGP's own dependencies to Maven Central, which 429s cloud sessions). Kotlin/Gradle daemons at 4 GB (K2 ran out at 2 GB). Lab sweep, max composable calls per frame on the headset, same machine before → after step 2: Home idle 75→40, Chatbox 616→434, Media 402→374, Settings 1,161→565, Sending 326→264, Home return 1,134 (unchanged: a first build). Step 1 before → after: Home 119→75, Chatbox 813→620, VRChat 1,390→985, Settings 2,067→1,267. Lab frame TIMES did not move measurably (noise ±30%); see labs.md limits.

### Public UI kit + Onboarding (UI revamp Phases 1-2, see docs/ui-revamp.md)

- **`PublicUiKit.kt`** (`ui/common/`): shared revamp components — `CompactSectionCard` (collapsible card whose collapsed header carries a live summary; expansion state in `rememberSaveable(title)`, or plain `remember` when `persistExpansion = false` — used by the Media tab cards that must re-open collapsed after tab navigation), `TogglePill` (icon+label+dot pill with long-press jump-to-edit via `detectTapGestures`), `StatusDot`/`KitStatusChip` (KitTone Neutral/Success/Warning/Error mapped to theme + Slime status colors), `LabeledRow`, `TutorialImage` (ON-DEMAND instruction image loaded by 1-based `index` from `TutorialImageStore` — NOT bundled in the APK; shows a spinner while downloading, tap → full-screen pinch-zoom dialog via Coil `rememberAsyncImagePainter`), `TrustNote`, `KitSectionHeader`. Design rule: "collapsed = status, expanded = control"; visual north star is the login screens, NOT the admin panel.

- **`VrcaDialogs.kt`** (`ui/common/`, used by BOTH builds): the shared confirm/picker primitives so every "are you sure?" popup reads identically AND matches the app's Gremlin card identity. **All dialogs are now card-styled** (`Dialog { ElevatedCard }`), NOT stock M3 `AlertDialog` — the user explicitly rejected the AlertDialog look as not matching the revamp. **`VrcaCardDialog(onDismiss, dismissOnOutsideTap=true, content)`** is the shared shell (near-full-width `ElevatedCard`, `surface` container, `large` rounded corners, 6dp elevation, 20dp side padding) every popup is built on — same visual language as `UpdateDialog`/`InstanceListDialog`. Build NEW dialogs on it, not `AlertDialog`. **`VrcaConfirmDialog(title, body, confirmLabel, onConfirm, onDismiss, destructive=false, confirmEnabled=true, dismissLabel="Cancel")`** — card dialog with a header (a warning glyph in an error-tinted circle when `destructive`), bodyMedium onSurfaceVariant, and a bottom actions row (Cancel `TextButton` + a filled confirm `Button`, error-colored when destructive).
  EVERY confirm popup routes through it: public Dismiss-all + VRChat sign-out (`VrchatPage.kt`), Settings VRChat/Discord sign-out (`VrcaSettingsPage.kt`), admin **Kill App**, Log out VRChat/Discord (`UsersTab.kt`), Retract release (`ReleasesTab.kt`). The Discord **risk-consent** + **login WebView** dialogs (`VrcaSettingsPage.kt`) and the Automations **preset peek** dialog (`AutomationsPage.kt`) are also rebuilt on `VrcaCardDialog`. **`VrcaDialogCopy`** holds the CANONICAL device-owner sign-out copy. **`VrcaTimeZoneDialog(currentMode, use24h, onSelect, onDismiss)`** — the NEW searchable, DST-correct timezone picker (replaced the old `VrcaSingleSelectDialog` UTC-offset grid): a search field + a "Device timezone" row + a scrollable list of zone rows labeled **"Paris 3:42 PM (UTC+2)"** with the offset computed LIVE (`TimeZones.kt`), so it follows daylight savings. `VrcaSingleSelectDialog` + `SelectPill` remain (SelectPill still drives the Cycle speed chip row).

- **`PanelScale.kt`** (`ui/common/`): headset fixed panel (see headset.md "Fixed panel"). `FixedPanel` (applied in `GremlinTheme` on the headset) lays the app out at 1024x640dp and scales it to the window; `PanelDialog` = `Dialog` whose content keeps that scale (`PanelScaled`, `LocalPanelDensity`), since each dialog window sets LocalDensity again. Every app dialog uses `PanelDialog` (`VrcaCardDialog` and so every VrcaDialogs dialog, the update sheet, event/instance dialogs, image zooms); no-op scale on phone builds. Material DropdownMenus keep real size. **`PanelDialogHold.held`**: while true every `PanelDialog` renders nothing (AppBoot sets it while the app is built hidden behind the boot screen; the dialog appears when it lifts).

- **`TimeZones.kt`** (`ui/common/`): timezone helpers shared by the VM + the picker. `resolveTimeZone(mode)` maps the stored `timeMode` string to a `java.time.ZoneId` — backward compatible with the LEGACY `"UTC+N"`/`"UTC-N"`/`"Device"`/`"UTC"` formats AND new IANA ids (e.g. `"Europe/Paris"`). New selections store IANA ids (DST-correct); old `"UTC+5"` values keep working. `timeZoneLabel(id, use24h)` builds the "City h:mm a (UTC±X)" label; `zoneOffsetLabel(zone)` is the live offset; `allTimeZoneIds` (cached, all real IANA zones sorted by live offset) + `commonTimeZoneIds` (curated major cities shown before search). `VrcaViewModel.currentTimeString()` now resolves via `resolveTimeZone(timeMode)`. **Country-name search (all countries)**: `zoneCountryName(id)` maps a zone to its country display name via ICU's region table (`android.icu.util.TimeZone.getRegion(id)` → ISO code → `Locale("", code).displayCountry`, cached) — so searching "japan" finds `Asia/Tokyo`, "france" finds `Europe/Paris`, etc., for EVERY country with no hand-maintained list (minSdk 26, ICU available). `countrySynonyms` adds colloquial aliases ("usa"/"uk"/"holland"/"uae"/…). The picker filter (`VrcaDialogs.kt` `VrcaTimeZoneDialog`) matches city, region, country name, zone id, and offset label.

### Performance rules (every screen; on the headset VRC-A shares the CPU with VRChat, ~93% busy)
Learned on the boot screen (docs/systems/onboarding-startup.md "Main-thread cost"); they apply to all UI, especially the revamp.
- **Animations repaint, they don't rebuild.** Read animated values only in draw/layout lambdas: `Modifier.graphicsLayer { }`, `drawBehind { }`, `offset { }`, or the cheap-by-construction helpers in `ui/common/Motion.kt` (`animatedOutline`, `widenIn`, `layerAlpha`, which take lambdas). Never pass `anim.value` / `by animate*AsState` values into `Modifier.alpha/scale/background/border` or down into child composables: that re-runs the whole subtree every frame. A short one-off colour change on a single leaf (e.g. a `Text` colour) is fine; anything continuous (pulses, infinite transitions, reveals) is not.
- **No state written every layout/frame.** `onGloballyPositioned { state = it }` (worst with `neverEqualPolicy`) rebuilds whoever reads it on every layout pass. Keep coordinates in a plain `remember { arrayOfNulls(...) }` holder read where it's drawn, and expose a one-time boolean (`placed`) as state.
- **Nothing slow while composing.** No disk reads, `EncryptedSharedPreferences`/Keystore, network, JSON parsing or big list building in a composable body: `remember` it, or load it in a `LaunchedEffect` on `Dispatchers.IO`. Ask expensive questions once, when needed, not as a `val` recomputed on every recomposition.
- **Narrow inputs.** Pass the values a composable shows (or a lambda), not the whole ViewModel, when it's deep in the tree; a flag that flips once (like boot finishing) goes in as `State`/lambda read only where needed, never as a parameter of a big tree.
- **Lists:** `LazyColumn`/`LazyRow` items get stable `key`s; derived lists use `remember(inputs)` / `derivedStateOf`.
- **Loading animations:** drawn in Compose with the clock read only while drawing (the Boot Cats, `app/BootCat.kt`). An `AnimatedVectorDrawable` would keep moving through a busy main thread (RenderThread), but the user chose Compose for every Boot Cat (2026-10-30: APK size, and AVD loading is itself main-thread work); a long stall can pause the loop and shows in the debug stall recorder. Ask before adding an AVD.
- **Big first builds:** build hidden while nothing animates (the boot screen builds Home behind itself), or split them with `StagedBuild` (`ui/common/StagedBuild.kt`): `val build = rememberStagedBuild(n)`, then `build.Step(k) { ... }` around later parts, so one step arrives per frame (on-screen parts in step 0; `build.done` before scrolling to a late part). Tab pages do this: the tab `Crossfade` starts at alpha 0, so later steps are invisible. Staging only happens where `LocalStagedBuild` is true, which `VrcaScreen` sets for pages entering through a TAB SWITCH; a page that appears without a fade (cold start, tabbing back into a recreated app) builds at once (staged there, Home's blocks visibly popped in one at a time: user report). Settings (6 steps) and Home (3) are staged; lab sweep: Settings' worst frame 4,126 → 948 composable calls, Home on return 3,143 → 1,426. The VRChat tab is a `LazyColumn` (builds only what's visible), so it isn't staged.
- **Everything shown is watched state (no stale info).** A composable may only SHOW values Compose watches: `mutableStateOf`/`mutableStateListOf`/`mutableStateMapOf`, a `Flow`/`StateFlow` collected with `collectAsState()`, or a `derivedStateOf` of those. Never show a plain field, a plain `object` var, `StateFlow.value`, SharedPreferences/encrypted-store/disk reads or the clock read straight in a composable body: they only look current because something else happened to redraw the screen, and they go stale when it doesn't (and under strong skipping, which is on, always). When the source isn't observable, copy it into state where it changes (e.g. a view-model `mutableStateOf` set on sign-in/out), or poll it into state with a ticker (`LaunchedEffect { while (true) { x = read(); delay(1000) } }`) only while the screen is visible. Reading a plain value inside an event handler or effect is fine; a one-time `remember { read() }` is fine only for values that can't change while that screen is up. New screens and every redesign follow this; check a screen by changing each source (lab `set`/`preset`) and seeing it update.
- **Known stale-prone spot (strong skipping is on, so fix when the Chatbox editor is redesigned):** Chatbox editor character counters (`AutomationsPage` `resolvedLengthOf = { vm.resolveTokens(it).length }`, ~7 sites: tokens read the clock, weather, battery, presence, OSC params; fix: a 1 s tick read inside the lambda while the editor is open). FIXED: the VRChat name / signed-in state is now `VrchatAuthManager.session` (a `StateFlow<StoredSession>`, vrchat-connection.md), read by the boot greeting, VRChat tab header, Home setup health and Settings → Accounts. Before, those read the encrypted store in the composable body: in the lab the old build showed "Not signed in" on the VRChat tab and "Signed out, chatbox sending is blocked" in Settings while signed in, whenever the store hadn't opened within the main-thread wait. The boot screen was audited and follows the rule.
- **Strong skipping (on since the Compose 1.12 step):** composables skip when every argument is the same instance (unstable types, like `VrcaViewModel`) or equal (stable types), and lambdas are remembered by what they capture. This removed most of the old tab-switch cost (the `Crossfade` re-ran the OUTGOING page: Settings' worst frame 1,161 → 565 calls). The price: in-place mutation and plain-value reads never update the screen (checklist above).
- **Check it:** run the UI Lab lag check on the screens a change touches (`perf start x` … `perf stop`, docs/systems/labs.md): no runs of frames each re-running VRC-A composables during an animation, no unexpected heavy frames.
